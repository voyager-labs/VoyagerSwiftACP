# Product Pillar

## PP01. System Accumulation

### 정의

- 파일 관리가 일회성 정리로 끝나지 않고, 시간이 지날수록 기준과 구조가 계속 쌓이는 방향으로 작동하게
  하는 원칙
- 프로퍼티, 콜렉션, 워크플로, 실행 결과가 다음 작업에도 남아 이후 파일 작업의 비용을 낮추는 누적
  구조

### 목적

- 한 번 만든 파일 정리 기준과 작업 구조가 이후 작업에도 계속 남게 하기
- 반복될수록 파일 관리 체계가 더 정교해지고 다음 작업 비용이 줄어들게 하기

### 설계 원칙

- 파일과 프로퍼티의 연결이 누적되어 이후 관계 기반 활용으로 이어질 수 있는 구조
- 한 번 만든 기준과 실행 결과가 이후에도 다시 활용될 수 있는 구조
- 실행 결과와 작업 흔적이 이후 판단과 재사용의 기반으로 남는 구조
- 사용자의 파일 체계가 시간이 지날수록 더 풍부해지는 방향의 설계

## PP02. Property Expansion

### 정의

- 파일을 이름과 위치 중심이 아니라, 상태, 주제, 대상자, 활용 목적 같은 프로퍼티 중심으로 이해하는
  원칙
- 시스템 메타데이터와 작업 맥락 프로퍼티를 함께 사용해, 파일을 지금 해야 할 일의 단위로 다시 읽게
  하는 구조
- 프로퍼티를 파일 설명용 보조 정보가 아니라, 이후 탐색, 정돈, 재사용 방식을 결정하는 기준으로 남게
  하는 기반

### 목적

- 업무 맥락 위에 쌓이는 파일 정리 기준 형성
- 여러 위치와 도구에 흩어진 파일을 현재 일의 기준으로 다시 찾고 다시 이해할 수 있는 기반 마련
- 파일과 프로퍼티의 연결이 누적되어 이후 관계 기반 활용으로 이어질 수 있는 기반 마련

### 설계 원칙

- 파일의 위치만이 아니라 프로퍼티 집합을 함께 기준으로 삼는 구조
- 일회성 태그가 아니라 계속 남는 탐색·정리 기준으로서의 프로퍼티
- 제품, 고객, 투자자, 출시 같은 실제 업무 맥락을 담는 프로퍼티 구조
- 사용자가 직접 정의한 프로퍼티와 시스템이 수집한 프로퍼티를 함께 다룰 수 있는 구조
- 같은 프로퍼티가 탐색, 콜렉션, 액션, 자동화 전반에서 같은 의미로 참조되는 일관성

## PP03. Logical Collections

### 정의

- 정의된 프로퍼티 조건에 따라 파일을 동적으로 불러오는 논리적 집합
- 물리적 위치를 바꾸지 않고도 파일을 작업 단위로 다시 불러오고 다시 활용하게 하는 구조

### 목적

- 여러 위치에 흩어진 파일을 다시 하나의 작업 집합으로 불러오고 다룰 수 있게 하기
- 같은 자산을 여러 목적에 반복해서 써도 정리 기준이 무너지지 않게 하기
- 일회성 검색 결과가 아니라, 다시 열어 쓸 수 있는 의미 있는 작업 집합 만들기

### 설계 원칙

- 폴더의 대체 위치가 아니라 현재 작업에 필요한 파일 집합을 정의하는 방식
- 같은 파일이 여러 콜렉션에 자연스럽게 포함될 수 있는 구조
- 다시 열었을 때도 같은 기준으로 파일을 재구성할 수 있는 콜렉션
- 작업 흐름 안에서 다시 열고 활용할 수 있는 저장된 콜렉션

## PP04. AI Agent Integration

### 정의

- 파일을 찾고 정리하고 활용하는 흐름 안에 AI 에이전트를 같은 맥락의 실행 주체로 통합하는 방식
- 사용자의 맥락을 바탕으로 필요한 후속 작업을 같은 맥락 안에서 수행하게 하는 구조

### 목적

- 파일 관리 체계 구축의 초기 비용과 지속 운영 부담 감소
- 파일 탐색, 정리, 활용, 산출물 생성을 하나의 흐름 안에서 이어가게 하기

### 설계 원칙

- 현재 파일 맥락과 선택 상태를 작업 범위로 삼아 동작하는 에이전트
- 에이전트의 응답과 실행 결과가 파일, 프로퍼티, 콜렉션 같은 객체와 연결되어 반영되는 구조
- 파일 탐색, 정리, 활용, 후속 작업이 에이전트 사용 전후로 끊기지 않고 하나의 흐름으로 이어지는 구조

## PP05. Repeatable Workflows

### 정의

- 반복되는 파일 작업 절차를 저장하고 다시 호출할 수 있게 하는 워크플로 구조
- 필요할 때 수동으로 실행할 수도 있고, 규칙과 트리거를 붙여 자동 실행으로 확장할 수도 있는 실행 방식

### 목적

- 반복되는 파일 작업을 매번 처음부터 다시 구성하지 않게 하기
- 같은 절차를 상황에 맞게 다시 실행하거나 자동으로 돌릴 수 있게 하기
- 정리, 활용, 공유 준비 같은 반복 작업을 일관된 방식으로 수행하게 하기

### 설계 원칙

- 사용자가 직접 실행하거나 저장해 다시 호출할 수 있는 워크플로
- 수동 실행과 자동 실행이 같은 워크플로 구조를 공유하는 방식
- 현재 파일 맥락이나 저장된 콜렉션을 입력으로 삼을 수 있는 워크플로
- 사람이 이해하고 수정할 수 있는 단계와 조건으로 유지되는 워크플로
