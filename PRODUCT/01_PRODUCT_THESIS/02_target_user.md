# Target User

## 핵심 타깃

### 1. 직접 빌더형 초기 테크 스타트업 파운더

초기 테크 스타트업에서 제품 설계, 개발, 출시 준비, 고객 대화, 투자자 커뮤니케이션을 직접 함께
수행하며, 문서, 피치덱, 데모 자산, 스크린샷, 코드 파일을 반복적으로 다시 찾고 정리하고 재사용해야
하는 사용자

#### 업무 맥락

- 초기 단계의 소규모 조직에서 제품 개발과 사업 운영의 여러 업무를 직접 함께 처리한다.
- 문서, 시각 자료, 코드처럼 성격과 포맷이 다른 파일과 자료를 같은 업무 흐름에서 함께 다룬다.
- 제품 개발, 외부 커뮤니케이션, 운영 의사결정처럼 목적이 다른 작업 사이를 자주 전환한다.
- 파일이 로컬 폴더, 클라우드 스토리지, 여러 작업 도구를 거치며 서로 다른 위치에 나뉘어 쌓인다.
- 같은 파일이라도 현재 업무 맥락에 따라 찾는 기준과 함께 다뤄야 할 자료 구성이 달라진다.

#### 행동 패턴

- 파일 정리의 필요성은 느끼지만 늘 우선순위에서 밀려, 필요할 때마다 관련 파일과 자료를 다시 찾게
  된다.
- 같은 자산을 제품 개발, 고객 공유, 투자자 커뮤니케이션처럼 서로 다른 맥락에 맞게 반복해서 가공하고
  재사용한다.
- 문서, 화면 캡처, 데모 자산, 코드 산출물의 최신 상태를 그때그때 확인해 가며 다음 산출물을 만든다.
- 파일을 이름이나 저장 위치보다 이번 출시, 이번 미팅, 이번 업데이트처럼 당장의 일 단위로 먼저
  떠올린다.

#### 적합성 신호

- 일의 맥락이 바뀔 때마다 필요한 파일을 다시 찾느라 시작이 자주 끊기는 사람
- 같은 제품 자산을 제품 개발, 고객 공유, 투자자 커뮤니케이션처럼 다른 목적에 맞게 계속 다시 꺼내
  쓰는 사람
- 필요한 파일을 바로 꺼내 쓰는 일이 늘 먼저라, 정리와 구조를 잡는 일은 계속 뒤로 미루게 되는 사람

## 예외

- macOS가 아닌 Windows, Web 환경에서만 주로 작업하는 사용자
- 개인이 파일 체계를 따로 만들지 않아도 될 만큼 조직 차원의 운영 시스템이 이미 강하게 정착된 사용자
- 업무 결과물이 파일보다 SaaS 도구 내부 객체 중심으로 남아, 로컬 파일을 다시 찾고 정리하고
  재활용하는 문제가 핵심이 아닌 사용자
- 문서 공동 편집, 채팅, 프로젝트 관리 같은 협업 워크스페이스가 파일 관리보다 더 핵심인 사용자
- 고도의 미디어 편집 기능이나 전문 뷰어 통합이 파일 브라우징보다 더 중요한 사용자
