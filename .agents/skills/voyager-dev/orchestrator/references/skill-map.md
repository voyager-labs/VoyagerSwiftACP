## Routing rules

- Load `../SKILL.md` first; role entry points refine, not replace, the orchestrator workflow.
- Prefer the narrowest role that owns the current task shape.
- Load multiple role entry points when work crosses boundaries, but keep one orchestrator decision record.
- When a Voyager package change also reorganizes package internals, load `../../../fsd-package-segmentation/SKILL.md`; when it changes products, targets, dependencies, or consumers, load `../../verifier/verification/references/package-integration-verification.md` before final verification.
- When creating packages or adding/moving types into packages, also load `../../verifier/verification/references/swift6-package-rules.md` to enforce Swift 6 strict concurrency rules.
- Do not move shared references into role folders unless all call sites are updated in the same change.
