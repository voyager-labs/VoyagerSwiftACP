## **Context**

1. ### **투자·제품 관련 설명 자료가 쌓이는 맥락**

- 핵심 상황   
  - Seed 라운드, 지원서, 발표, 내부 리뷰마다 시장 상황, 성장, 리텐션, 요금제 등 비슷한 질문에 답하는 문서를 계속 제작  
  - 답에 쓰인 숫자·차트·인용·사례가 피치덱, 지표 시트, 리서치, 제품 설명 문서, 업데이트 메일 등 여러 파일에 분산  
- 현재 방식  
  - 새 문서를 만들 때마다 이번 버전의 기준으로 삼을 파일을 다시 고르고, 질문별로 근거를 다시 조합  
  - 과거 라운드/미팅에서 어떤 파일·내용을 가져와 썼는지 시스템 상에 명시돼 있지 않아, 예전 산출물을 직접 열어보며 역추적하는 식으로 확인

2. ### **파일 정리 기준과 누적 방식**

- 핵심 상황  
  - 파일 이름, 폴더, 태그에 나름의 규칙은 있지만, 문서화돼 있지 않고, 시기·프로젝트·사람마다 적용 방식이 조금씩 상이함  
  - 피치덱, 리서치 PDF, 실험 결과 시트, 회고 노트, 스크린샷, CSV, 인보이스 등이 새로 생길 때마다 기존 것들과 섞여 상위 폴더에 계속 누적  
- 현재 방식  
  - 새로운 파일이 생기면 그때 떠오르는 기준으로 이름·위치를 정하고, 대략 맞는 상위 폴더에 넣는 선에서 정리를 마무리  
  - 규칙을 한 번에 재정비하기보다는 프로젝트마다 부분적으로 손보다가, 시간이 지나면 예전 방식과 새 방식이 섞여 일관성이 흐려지고, 삭제·이동·아카이브는 연기함

3. ### **반복되는 결산·업데이트·리뷰 작업의 파일 환경**

- 핵심 상황  
  - 매월 수입·지출을 확인하고, 필요할 때 월간 결산·내부 지표 리뷰·투자자 업데이트를 작성  
  - 이때 참고하는 결제 내역, 인보이스, 지표 시트, 실험 결과 문서 조합은 작업마다 조금씩 다르지만 기본 틀은 비슷함  
- 현재 방식  
  - 특정 달·분기의 결산이나 업데이트를 준비할 때마다 관련 파일을 다시 검색·모아서 임시 작업 세트 제작  
  - 자주 반복되는 작업이지만, 재사용 가능한 템플릿이 없어 준비 단계에 반복적인 작업이 소요

## **Pains**

1. ### **큰 문서 제작∙결정을 할 때마다 필요한 근거를 다시 모으느라 시작이 늦어짐**

- 동일한 질문(시장, 성장, 리텐션, 요금제)에 대한 근거가 파일별로 흩어져 있음  
- 어떤 슬라이드·지표·리서치를 이번 버전에 사용할지 판단을 매번 처음부터 다시 함  
- 과거 어떤 자료를 근거로 썼는지 문서상에 연결되지 않아, 이전 버전의 내용을 직접 열어 확인해야 함  
- 새 피치덱·제품 설명·전략 문서를 시작할 때 최소 1\~2시간이 자료 복원 작업으로 먼저 소모됨

2. ### **파일 정돈 규칙이 일관되지 않아, 최신 자료와 핵심 자료를 빠르게 판별하기 어려움**

- 파일명·폴더·태그 규칙이 작업 시점과 프로젝트마다 다르게 적용됨  
- 같은 종류의 파일이라도 표현 방식이 달라, 어떤 것이 “현재 기준”인지 파악 부담 발생  
- 오래된 규칙과 최근 규칙이 섞여 있어, 한 자료를 찾는 데 여러 후보를 열어봐야 함  
- 정리 체계에 대한 신뢰도가 낮아 파일 재사용·공유 시 확인 단계가 필수로 붙음

3. ### **정리·삭제가 불안해 쌓기만 하고, 불필요한 파일이 누적됨**

- “나중에 쓸 수도 있음” 판단으로 삭제를 미루는 파일이 지속적으로 누적  
- 정리 시점·방식·우선순위가 불명확해, 유지·이동·아카이브 결정을 내리기 어려움  
- 언제·어디서 다시 필요할지 몰라서 당장은 건드리지 않고 상위 폴더에 계속 남김  
- 중요 자료와 저가치 자료가 동일 계층에 쌓여 탐색 범위와 판단 시간이 커짐

4. ### **반복 작업이 매번 셋업부터 다시 시작됨**

- 매달 결제 내역·인보이스·지표를 다시 찾아 모아야 함  
- 어떤 파일·숫자를 기준으로 볼지 매번 처음부터 결정  
- 특정 월·분기의 정리 흐름이 템플릿으로 남지 않아, 결산/리뷰 작업이 매번 새 프로젝트처럼 느껴짐  
- 반복적 준비 부담이 계속 집중되어, 위임이나 팀 기반 운영이 어려워짐

## **Goals**

1. 큰 문서∙결정을 만들 때, 필요한 근거 세트(슬라이드·지표·리서치)를 바로 불러와 일부만 갱신하면 되는 상태  
2. 최소한의 정리 기준만으로도 최신 자료와 핵심 자료를 빠르게 구분할 수 있는 상태  
3. 삭제·이동·아카이브를 안심하고 실행해, 활성 작업 영역을 가볍게 유지할 수 있는 상태  
4. 결산·리뷰·업데이트 같은 반복 작업을 템플릿 기반으로 짧게 준비·마무리할 수 있는 상태

### **JTBD01. 질문별 근거 세트로 큰 문서 준비하기**

- 새 피치덱·투자자용 설명·제품·전략 문서를 만들 때, 시장·성장·리텐션·요금제 같은 반복 질문 목록을 기준으로 작업을 시작하고 싶다.    
- 각 질문에 대해 이번에 쓸 슬라이드·지표·리서치·사용자 사례 파일을 한 번에 모아 보고, 쓸 것과 교체할 것을 빠르게 고르고 싶다.    
- 과거 라운드·버전에서 어떤 설명과 근거를 썼는지 다시 참고할 때, 관련 파일을 일일이 뒤지지 않고 바로 확인하고 싶다.    
- 한 번 정리해 둔 질문별 근거 묶음을 다음 라운드·다음 버전의 출발점으로 삼아, “처음부터 다시 조립하는 일”을 줄이고 싶다.    
- 질문 단위를 기준으로 슬라이드·지표·리서치·사례 파일을 하나의 근거 세트로 묶어 저장할 수 있도록 지원해야 한다.    
- 저장해 둔 근거 세트를 새 문서에서 불러와, 일부만 교체·추가하는 식으로 재사용할 수 있도록 해야 한다.    
- 근거 세트와 실제 산출물(덱·문서)의 특정 부분이 서로 어떻게 연결돼 있는지, 최소한의 흔적이라도 추적할 수 있어야 한다.  

### **JTBD02.  현재 기준에 맞게 파일 구조를 이해하기 쉽게 유지하기**

- 같은 종류의 파일들이 어떤 이름·폴더·태그 규칙을 따라야 하는지, 지금 시점 기준의 단순한 원칙을 정해 두고 싶다.    
- 새 파일을 만들거나 저장할 때마다 그 원칙을 떠올려, 나중에 봐도 이해되는 방식으로 이름과 위치를 정하고 싶다.    
- 펀딩·제품·운영처럼 주요 영역 폴더를 열었을 때, 지금 작업에 직접 쓰는 파일과 과거·참고용 파일의 대략적인 구분이 구조만 봐도 느껴지길 원한다.    
- 구조가 흐트러졌다고 느껴질 때, 전체를 갈아엎지 않고도 특정 영역부터 조금씩 지금 기준에 맞게 다시 정리하고 싶다.    
- 이름·폴더·태그에 대한 간단한 정리 기준을 정의·수정·공유할 수 있는 공간을 제공해야 한다.    
- 파일을 저장하거나 이동할 때 이 기준을 참고해 이름·위치를 정하도록, 제안·자동완성·예시 등의 도움 수단을 제공해야 한다.    
- 영역별(예: Fundraising, Product)로 파일 목록을 보고, 작업용/참고용 정도로 가볍게 나눠 볼 수 있는 뷰나 필터를 제공해야 한다.    
- 폴더·파일 정리 작업을 특정 영역 범위 안에서만 적용·검토할 수 있도록, 정리 범위와 영향을 명확히 제한할 수 있어야 한다.  

### **JTBD03.  정리·보존·아카이브 작업을 안전하게 실행하기**

- 상위 폴더에 쌓인 옛 피치덱, 리서치 PDF, 중간 산출물, 스크린샷 중 당장 쓰지 않는 파일들을 따로 골라 보고 싶다.    
- 마지막 사용 시점이나 용도·연관 작업 등을 참고해, 어떤 파일은 그대로 보존하고 어떤 파일은 아카이브로 내리고 어떤 파일은 삭제해도 될지 스스로 기준을 세우고 싶다.    
- 정리·이동·삭제를 실행하기 전에 어떤 파일이 처리 대상인지 대략적인 리스트를 보고, 필요하면 일부만 먼저 시도해 본 뒤 나머지를 이어서 처리하고 싶다.    
- 한 번 정리·아카이브를 해도, 나중에 특정 파일이 다시 필요해지면 어디에서 찾아야 할지 감이 남아 있기를 원한다.    
- 최근 사용 여부·간단한 속성 등을 기준으로, 정리 후보가 될 만한 파일들을 한 화면에서 모아 볼 수 있도록 해야 한다.    
- 선택한 파일들에 대해 보존·이동·삭제 같은 처리를 묶어서 적용할 수 있도록, 일괄 작업 흐름을 제공해야 한다.    
- 정리 작업을 실행하기 전에 처리 대상과 처리 방식에 대한 요약을 보여주고, 여기서 범위를 줄이거나 일부만 적용하도록 조정할 수 있게 해야 한다.    
- 아카이브된 파일을 찾기 위한 최소한의 단서(폴더, 태그, 메모 등)를 유지해, 나중에 다시 필요해졌을 때도 검색·탐색이 가능하도록 해야 한다.  

### **JTBD04. 결산·리뷰·업데이트 같은 반복 작업을 다음 달에도 그대로 쓸 수 있게 만들기**

- 매달 결산·내부 지표 리뷰·투자자 업데이트를 준비할 때마다, 기본으로 함께 보는 결제 내역·인보이스·지표·실험 결과 파일 세트를 정해 두고 싶다.    
- 새로운 달이나 분기에도 이 세트를 불러와, 이번에 추가·제외할 파일만 정하고 곧바로 숫자·내용 업데이트로 들어가고 싶다.    
- 몇 번 같은 흐름을 돌린 뒤에는, 구조를 그대로 두고 내용(숫자·메시지)만 바꾸는 느낌으로 결산·리뷰·업데이트를 처리하고 싶다.    
- 이런 반복 작업을 나중에 팀원에게 넘겨도, 같은 순서와 기준으로 실행되길 원한다.    
- 결산·리뷰·업데이트 유형별로 실제 사용한 파일·지표 구성을 템플릿으로 저장할 수 있도록 해야 한다.    
- 템플릿을 기반으로 새로운 기간에 해당하는 파일 후보를 모아주고, 포함할 것과 제외할 것을 빠르게 선택·수정할 수 있도록 해야 한다.    
- 템플릿과 각 기간별 인스턴스를 구분해 관리하면서도, 둘 사이의 연결 관계(어떤 템플릿에서 나온 작업인지)를 확인할 수 있어야 한다.    
- 정의된 템플릿과 실행 흐름을 다른 사람과 공유·복제해, 팀 단위로 동일한 방식의 결산·리뷰·업데이트를 진행할 수 있도록 해야 한다.
