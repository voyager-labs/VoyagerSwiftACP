6. ## **Summary**

   1. ### **One-line Definition**

* 채팅에서 엔트리 변경∙삭제 같은 파괴적 작업을 요청하면, 컨텍스트 기반 실행 계획(드라이런 포함)을 제시하고 사용자 확인 후 실행하며 결과를 워킹셋과 히스토리로 남기는 흐름

  2. ### **Purpose**

* 채팅 기반으로 이름 변경/이동/삭제/태그 편집 등 파일 관리 변경 작업을 빠르고 안전하게 수행하기 위함  
* 변경 전 영향 미리보기(드라이런), 사용자 승인, 충돌/권한/부분 실패 처리, Undo/Redo 기준을 표준화해 실행 신뢰도를 확보하기 위함  
* 결과를 워킹셋으로 남겨 수동 정돈 및 워킹셋 저장 플로우로 자연스럽게 연결되도록 하기 위함

7. ## **Scope**

   1. ### **In-Scope**

      채팅 세션에서 지정한 컨텍스트(디렉토리/선택 엔트리/콜렉션/워킹셋) 내 파괴적 파일 작업 요청 처리

      지원 작업 범위

* 이름 변경(단일/배치)

* 이동/복제/압축/추출

* 태그/라벨 편집

* 권한 변경

* 휴지통으로 이동, 즉시 삭제(영구 삭제)

  안전 실행 절차

* 요청 해석 → 대상 확정 → 변경 미리보기(드라이런) → 사용자 확인(Confirm) → 실행 → 결과 보고

  실행 품질

* 진행 상태 표시, 부분 성공/실패 분리, 재시도/건너뛰기 단위 제어(정책에 따라)

* 실행 히스토리 및 Undo/Redo(가능 범위 내)

  결과 산출

* 변경 결과 워킹셋(예: Changed Entries) 생성 및 세션 내 링크 유지  
* 

  2. ### **Out-of-Scope**

* 검색 중심 워킹셋 구성(UC04)  
* 규칙 기반 콜렉션 정의/편집(UC03)  
* 문서/코드 본문 내용 편집(외부 앱 또는 별도 UC)  
* 스토리지 전역 주기/정책 기반 자동화(별도 자동화 UC)  
* 커스텀 프로퍼티 스키마 설계·대량 편집(CEP 고급 플로우)

8. ## **Flow**

   1. ### **Representative scenario**

* 사용자는 특정 프로젝트 디렉토리와 저장된 콜렉션을 스코프로 지정해 채팅을 연 상태다.  
* “지난 분기 자료 정리: 스크린샷 파일은 휴지통으로, pitchdeck 파일은 ‘Archive/2025Q3’로 이동, 이름 접두사 ‘2025Q3\_’로 맞춰줘.”라고 요청한다.  
* 시스템은 스코프에서 후보를 검색해 각 액션 대상과 변경 결과 미리보기를 제시하고, 덮어쓰기/이름 충돌/권한 이슈를 설명한다.  
* 사용자가 확인하면 단계별로 실행하고, 성공/실패 항목과 이유를 결과 워킹셋·로그로 남긴다.  
* 필요하면 “Undo 마지막 변경”으로 직전 변경을 되돌린다.

### 

  2. ### **Variations**

* Variation A: 단일 액션 집중 실행  
  * “선택한 파일만 이름 접두사 통일” 같이 한 가지 변경만 요청하고 빠르게 확정/실행.  
* Variation B: 대량 배치 변경  
  * 수백 개 이상의 엔트리에 대한 이동·삭제·리네임을 순차/배치로 실행하며 진행률과 부분 실패를 요약.  
* Variation C: 안전 모드(휴지통만 사용)  
  * 즉시 삭제를 비활성화하고 모든 삭제를 휴지통 경유로만 수행.  
* Variation D: 충돌 회피 규칙 우선  
  * 이름 충돌 시 자동으로 접미사 번호 부여(예: \_1, \_2) 또는 타임스탬프 부여 규칙 적용.

  3. ### **Exceptions**

* Zero candidate / 조건 불일치  
  * 스코프/조건에 맞는 대상이 없으면 “후보 없음” 상태와 완화 힌트(기간/타입/패턴)를 제시.  
* Permission error / 잠금 파일  
  * 접근/변경 권한 부족, 클라우드 동기화 잠금 등은 실패 항목으로 분리, “Finder에서 열기/권한 다시 요청” 등 우회 제안.  
* Name conflict / target path conflict  
  * 이동/복제/리네임 시 충돌 발견 시 덮어쓰기/새 이름/건너뛰기 옵션을 명시적으로 요구. 확인 없이는 자동 덮어쓰기 금지.  
* Long-running / partial failure  
  * 대량 작업은 진행 표시와 중간 실패 요약을 제공, 재시도/건너뛰기 단위 제어 허용.  
* Immediate delete (영구 삭제) 보호  
  * 즉시 삭제는 별도 경고 레벨과 2단 확인(예: “영구 삭제 동의”)을 요구.  
* Undo 불가 범위  
  * 권한/네트워크 이슈로 일부 변경은 완전 Undo가 불가할 수 있으며, 가능한 범위만 되돌림을 안내.
