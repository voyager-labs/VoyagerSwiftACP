# TSV 규칙

이 레포의 인벤토리/IA 테이블 등 표 형태 자료는 `data.tsv` + `schema.json` 조합으로 유지합니다.
TSV는 **머신과 사람이 함께 신뢰하는 SSOT**이며, 기본적으로 GitHub에서 TSV를 그대로 읽고 리뷰하는 것을 전제로 합니다.

## 기본 원칙

- **TSV는 SSOT**: 기획/결정의 정본은 TSV에 있고, 문서(MD)는 설명/컨텍스트를 담습니다.
- **결정론적(deterministic)**: 같은 입력은 항상 같은 출력(정렬/표현)이어야 합니다.
- **리뷰 가능성**: diff가 의미 있게 보이도록 대량 재정렬/포맷 흔들림을 피합니다.

## 파일 구조

- 각 테이블은 디렉토리로 분리합니다.
  - `data.tsv`: 데이터
  - `schema.json`: 컬럼 정의(이름/타입/설명)

예:

```text
PRODUCT/03_INFORMATION_ARCHITECTURE/
  MENUS/
    data.tsv
    schema.json
```

## 형식 규칙 (하드 룰)

- **빈 행(완전히 비어 있는 줄) 금지**
  - 구분/섹션을 표현하기 위해 빈 줄을 넣지 않습니다.
- **헤더 포함, 모든 행은 동일한 컬럼 수를 가져야 함**
  - 헤더의 컬럼 수보다 적거나 많은 필드를 가진 행은 금지합니다.
  - 값이 비어 있어도 해당 컬럼의 자리는 유지합니다.
- **멀티라인 셀 금지**
  - TSV 셀 안에 줄바꿈(\n)을 넣지 않습니다.
- **탭은 구분자만**
  - 셀 값 자체에 탭 문자를 포함하지 않습니다.

## 빈 값/미정 값 표기

TSV에서 빈 셀은 가독성이 떨어질 수 있으므로, 아래 표기를 표준으로 사용합니다.

- 값 없음 / 해당 없음(의도적으로 비어 있음): `-`
- 채워야 함 / 미정(아직 작성하지 못함): `TBD`

## AI 초안 표기

Google Drive의 셀 색상 범례(= AI 초안/주의 필요)를 대체하기 위해, **셀 값 맨 앞에만** AI 프리픽스를 붙입니다.

- 표기: `<<AI>> `
- 의미: "AI가 작성한 초안이므로 사람이 검토가 필요하다"

규칙:
- `<<AI>>`는 **셀 맨 앞**에서만 사용합니다.
- `<<AI>>` 뒤에는 **공백 1개**를 둡니다.
- 사람이 검토/재작성/수정해 신뢰 가능한 상태가 되면 `<<AI>> `를 제거합니다.

권장 적용 컬럼:
- 긴 텍스트 컬럼(예: `description`, `summary`, `edge_cases`, `acceptance_criteria`)

비권장:
- 식별자/키/enum 컬럼(예: `feature_id`, `category_key`, `status`)

## ID/정렬 규칙

- 테이블에 안정적인 ID가 존재한다면(예: `feature_id`), 파일은 기본적으로 **ID 오름차순 정렬**을 유지합니다.
- 정렬 기준이 ID가 아닐 경우, 해당 테이블 디렉토리의 README 또는 추후 생성 문서에서 정렬 기준을 명시합니다.

## 리스트/다중값 컬럼

리스트가 필요한 컬럼은 스키마/테이블 단위로 delimiter를 고정합니다.

- 권장: `|` (예: `FMW-001|EVM-002`)
- 빈 리스트: `-`

## schema.json 규칙

- `schema.json`의 `columns[].name` 순서가 TSV 헤더 순서와 동일해야 합니다.
- 타입은 최소한으로 운영합니다(예: `string`, `number`).

## 변경 운영 규칙

- 의미 있는 변경은 PR로 남깁니다.
- 대규모 변경(정렬 변경/포맷 정규화)은 커밋을 분리해서 리뷰가 가능하도록 합니다.
