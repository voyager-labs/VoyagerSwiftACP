# Story 117.9: Helper ProcessRunner async 전환 및 동시성 정리

## Status
Done

## Story
**As a** 개발자/운영자,  
**I want** Helper의 backend 실행 흐름을 async 기반으로 정리하길,  
**so that** backend 실행/종료 흐름이 블로킹 없이 안정적으로 동작한다.

## Story Context
- Epic 연계: VOY-117 Helper/Backend 생명주기 일관화 목표의 async 정리 파트
- 목적: backend 실행 흐름을 non-blocking으로 전환하고 경쟁 호출을 안정화한다.

## Acceptance Criteria
1. `ProcessRunner.startIfNeeded()`는 async로 전환되고, 호출자는 `await`로 결과를 기다릴 수 있다.
2. start 중복 호출은 단일 인플라이트 가드로 보호되어 동시 실행이 발생하지 않는다.
3. `stop()`은 진행 중인 start 흐름을 중단하고, 종료 후 재시작이 발생하지 않는다.
4. `HelperLifecycle`는 async start/stop 흐름에 맞춰 호출 구조를 조정한다. (신호 핸들러 포함)
5. `VoyagerHelperApp.main()`은 async start를 안전하게 트리거하며 기존 런루프 동작을 유지한다.
6. 변경 후에도 Helper의 backend 기동 동작이 회귀하지 않는다.
7. 경쟁 시나리오(`start` 중 `stop`, `stop` 직후 `start`)에서 backend가 중복 실행되지 않는다.

## Tasks / Subtasks

## Dev Notes
- 대상 파일:
  - `apps/macos/Voyager/VoyagerHelper/Infrastructure/ProcessRunner.swift`
  - `apps/macos/Voyager/VoyagerHelper/Infrastructure/HelperLifecycle.swift`

- `ProcessRunner`는 `actor`로 전환해 단일 인플라이트 작업을 보장한다. (`isStarting`/`stopRequested` 사용)
- `stop()` 호출 시 진행 중인 start 흐름을 중단하고, 이후에는 backend를 재실행하지 않도록 보호한다.
- 경쟁 시나리오 처리 규칙:
  - `start` 중 `stop` 호출 시: 진행 중 start 작업 취소 + 프로세스 종료
  - `stop` 직후 `start` 호출 시: 새 start 작업만 허용 (이전 작업 재사용 금지)
