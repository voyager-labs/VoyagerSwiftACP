# Story 117.6: SwiftLog 도입 및 로그 교체

## Status
Done

## Execution Order
1.5 (Story 2 이전)

## Story
**As a** 개발자/운영자,  
**I want** Voyager와 VoyagerHelper의 로그가 일관된 로깅 체계로 수집되길,  
**so that** 디버깅/운영 시 로그 레벨과 출력 경로를 안정적으로 추적할 수 있다.

## Acceptance Criteria
1. Voyager와 VoyagerHelper 타깃 모두에 `swift-log` 의존성이 추가된다.
2. Voyager와 VoyagerHelper 모두 stderr(StreamLogHandler) 기반을 사용한다.
3. `fputs`/`print` 사용 로그가 모두 `Logger` 호출로 교체된다.
4. 기존 로그 메시지의 의미(시작/오류/포트 할당)는 유지되며 레벨이 명확히 구분된다.
5. 로그 라벨은 `Voyager` / `VoyagerHelper`로 구분된다.
6. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Dev Notes
- Voyager와 Helper 모두 stderr 기반 로그가 디버깅에 유리하므로 StreamLogHandler를 사용한다.
- 로그 레벨 매핑 기준 예: 시작/상태=info, 오류=error.
- 참고: `docs/voy-117/epic.md#epic-goal`
- Helper의 backend stderr 포워딩은 유지한다.
