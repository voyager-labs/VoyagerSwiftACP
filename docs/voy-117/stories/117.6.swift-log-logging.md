# Story 117.6: SwiftLog 도입 및 로그 교체

## Status
Draft

## Story
**As a** 개발자/운영자,  
**I want** Voyager와 VoyagerHelper의 로그가 일관된 로깅 체계로 수집되길,  
**so that** 디버깅/운영 시 로그 레벨과 출력 경로를 안정적으로 추적할 수 있다.

## Acceptance Criteria
1. Voyager와 VoyagerHelper 타깃 모두에 `swift-log` 의존성이 추가된다.
2. Voyager는 OSLog 기반(LogHandler)을 사용하고, VoyagerHelper는 stderr(StreamLogHandler) 기반을 사용한다.
3. `fputs`/`print` 사용 로그가 모두 `Logger` 호출로 교체된다.
4. 기존 로그 메시지의 의미(시작/오류/포트 할당)는 유지되며 레벨이 명확히 구분된다.
5. 로그 라벨은 `Voyager` / `VoyagerHelper`로 구분된다.
6. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Tasks / Subtasks
- [ ] `swift-log` 패키지 추가 (AC: 1)
- [ ] 로그 핸들러 초기화 (Voyager: OSLog, Helper: stderr) (AC: 2, 5)
- [ ] 기존 `fputs`/`print` 로그 교체 (AC: 3, 4)
  - [ ] `VoyagerHelper/VoyagerHelperApp.swift`
  - [ ] `VoyagerHelper/Infrastructure/ProcessRunner.swift`
  - [ ] `Voyager/FileManager/Views/InspectorPaneView.swift`
- [ ] 수동 QA 수행 (AC: 6)

## Dev Notes
- Helper는 stderr 기반 로그가 디버깅에 유리하므로 StreamLogHandler를 사용한다.
- App은 Console.app에서 수집 가능하도록 OSLog 기반을 사용한다.
- 로그 레벨 매핑 기준 예: 시작/상태=info, 오류=error.
- 참고: `docs/voy-117/epic.md#epic-goal`

### Testing
- 수동: Voyager-Dev 실행 시 OSLog에 앱 로그가 기록되는지 확인.
- 수동: Helper 실행 시 stderr 로그가 계속 출력되는지 확인.
- 수동: 기존 로그 메시지가 Logger로 대체되었는지 확인.
