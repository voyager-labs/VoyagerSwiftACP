# Story 117.4: UI 엔드포인트 탐지 정리

## Status
Ready

## Story
**As a** 사용자,  
**I want** UI가 backend 엔드포인트를 자동 탐지하길,  
**so that** 동적 포트에서도 안정적으로 요청을 보낼 수 있다.

## Acceptance Criteria
1. UI는 `pgrep -f "Voyager Backend"` + `lsof -n -P -a -iTCP -sTCP:LISTEN -p <PID>`로 endpoint를 구성한다.
2. `PUBLIC_BACKEND_PORT=0` 환경에서도 endpoint 탐지가 정상 동작한다.
3. backend 재기동 시 UI는 endpoint를 재탐지한다.
4. runtime config/BackendState 공유 로직은 제거된다.
5. PID는 프로세스명으로부터 확보하고, lsof로 LISTEN 포트를 추출해 URL을 구성한다.
6. 다중 PID 매칭 시 `ps`의 `etime` 기준으로 시작 시간이 가장 최근인 프로세스를 우선 선택한다.
7. URL은 `PUBLIC_BACKEND_HOST` + 탐지한 포트로 구성한다.
8. source/bundled 모두 `Voyager Backend` 프로세스명 탐지가 가능하다.
9. 기존 UI 흐름과 충돌하지 않는다.
10. 탐지 실패 시 1초 간격으로 3회 자동 재시도한다.
11. 3회 실패 후에는 로그만 남기고 `nil`을 반환한다.
12. 실패 후에도 UI는 프리즈되지 않고 브라우징이 가능해야 한다.
14. 변경 전후 회귀 동작이 수동 QA로 확인된다.
15. `PUBLIC_BACKEND_PROCESS_NAME`는 `.env`에서만 읽고 런처 env는 사용하지 않는다.

## Dev Notes
- 우선순위: Story 117.4를 선행한다. endpoint 탐지 확정 전에는 재기동/헬퍼 정책 QA가 막히므로 먼저 정리한다.
- Story 117.3의 Helper 핸드셰이크 제거는 후속으로 진행하며, 본 스토리는 UI 탐지 로직에 집중한다.
- UI 클라이언트는 `apps/macos/Voyager/Voyager/App/Clients` 아래에 신규 추가를 고려한다.
- 프로세스명은 source/bundled 모두 `Voyager Backend`를 사용한다.
- 프로세스명 SSOT: `.env`의 `PUBLIC_BACKEND_PROCESS_NAME`만 사용한다. 런처 env는 `APP_ENV`/`BACKEND_MODE`/`VOYAGER_PROJECT_ROOT`만 허용한다.
- UI 앱에서도 `SwiftDotenv`로 `.env.{APP_ENV}`를 로드해 `PUBLIC_BACKEND_PROCESS_NAME`을 읽는다.
- endpoint 구성은 `PUBLIC_BACKEND_HOST`를 기준으로 한다.
- `PUBLIC_BACKEND_PROCESS_NAME`/`PUBLIC_BACKEND_HOST` 이외의 env는 탐지 로직에서 읽지 않는다.
- 다중 PID는 `ps -o pid= -o etime=` 결과를 사용해 경과 시간이 가장 짧은 PID를 선택한다.
  - `etime` 포맷(`[[dd-]hh:]mm:ss`)을 초 단위로 파싱해 비교한다.
  - 오버헤드: `ps` 1회 호출 + 문자열 파싱(수 ms 수준 예상). PID 수가 적은 환경에서는 체감 영향 없음.
- Helper의 stderr 포트 파싱/핸드셰이크는 제거하고 UI가 직접 탐지한다. (117.3 범위)
- 의존성: `docs/voy-117/stories/117.3.backend-restart-management.md`의 핸드셰이크 제거 방향과 일치해야 한다.
- `pgrep`/`lsof` 실행은 UI 프리즈 방지를 위해 백그라운드에서 수행한다.
- `pgrep` 결과가 없거나 `lsof`에서 LISTEN 포트가 없으면 실패로 간주하고 재시도 카운트를 증가한다.
- `PUBLIC_BACKEND_HOST`가 없으면 탐지 실패로 처리하고 로그만 남긴다.
- runtime config/BackendState 관련 코드는 현재 코드베이스에서 발견되지 않아, 존재 여부 확인 후 결과를 문서화한다.
- 통합 지점은 신규 `BackendEndpointClient`(예: `apps/macos/Voyager/Voyager/App/Clients/BackendEndpointClient.swift`)로 캡슐화하고, 실제 API 호출 지점에 의존성으로 주입한다.
- 참고: `docs/voy-117/epic.md#epic-goal`
- 참고: `docs/architecture/tech-stack.md#기술-요약`
- 참고: `docs/architecture/source-tree.md#핵심-모듈과-역할`

- 수동: 다중 PID 매칭 시 시작 시간이 가장 최근인 프로세스가 선택되는지 확인.
