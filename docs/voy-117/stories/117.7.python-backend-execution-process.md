# Story 117.7: Python 백엔드 실행 프로세스 정리

## Status
Draft

## Story
**As a** 개발자/운영자,  
**I want** BACKEND_MODE에 따른 Python 백엔드 실행 경로와 환경 구성을 단일 기준으로 정리하고,  
**so that** source/bundled 환경 모두에서 재현 가능한 실행 프로세스를 유지할 수 있다.

## Acceptance Criteria
1. Python 백엔드 실행 커맨드/경로/인자 결정 로직이 단일 진입점으로 정리된다.
2. `source` 모드는 `uv run` 기반 로컬 실행으로 정의되어 문서와 코드가 일치한다.
3. `bundled` 모드는 앱 번들 내 바이너리 실행으로 정의되어 문서와 코드가 일치한다.
4. `APP_ENV`가 백엔드 프로세스 환경 변수로 전달되고, `Debug=dev`/`Release=prod` 매핑이 유지된다.
5. 실행에 필요한 기본 환경 변수 집합이 명시되고(예: `BACKEND_MODE`, `APP_ENV`), 누락 시 기본값 동작이 정의된다.
6. 실행 프로세스 변경 후에도 `Voyager Backend` 프로세스명 탐지가 유지된다.

## Tasks / Subtasks
- [ ] 실행 커맨드/경로 결정 로직 정리 (AC: 1, 2, 3)
  - [ ] `source` 모드의 `uv run` 실행 경로와 작업 디렉터리 명시
  - [ ] `bundled` 모드 바이너리 경로 결정 로직 명시
- [ ] 실행 환경 변수 구성 정리 (AC: 4, 5)
  - [ ] 기본 환경 변수 목록 정의 및 전달 방식 확정
  - [ ] 누락 시 기본값 동작 명시
- [ ] 프로세스명 유지 여부 확인 및 문서화 (AC: 6)
- [ ] 관련 문서 갱신 (LIFECYCLE/ENV/구성 문서) (AC: 2, 3, 4)

## Dev Notes
- Helper가 백엔드를 실행하는 진입점은 `VoyagerHelper/Infrastructure/ProcessRunner.swift`이다.
- 실행 경로/환경 변수 분기 기준은 `BACKEND_MODE`를 최상위로 유지한다.
- `APP_ENV`는 빌드 Configuration 매핑을 그대로 사용하고, Helper 실행 시 그대로 전달한다.
- `source` 모드에서 `VOYAGER_PROJECT_ROOT`를 이용해 작업 디렉터리를 결정하는 로직과 충돌하지 않게 정리한다.
- 참고: `docs/voy-117/stories/117.1.voyager-project-root.md`, `docs/voy-117/stories/117.5.backend-mode-db-path.md`

### Testing

- 수동: `Voyager-Prod`에서 `bundled` 모드 바이너리가 실행되는지 확인.
