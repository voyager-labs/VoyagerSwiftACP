# Story 117.3: Backend 재기동 관리 강화

## Status
Draft

## Story
**As a** 사용자,  
**I want** backend가 중단되더라도 Helper가 복구하길,  
**so that** Voyager 기능이 지속적으로 동작한다.

## Acceptance Criteria
1. Helper는 backend 종료를 감지하고 backoff 정책에 따라 재기동을 시도한다.
2. Helper 종료 시 backend 프로세스는 정상 종료된다.
3. 재기동 후에도 포트 할당 로그/파싱이 정상 동작한다.
4. 최대 재시도 초과 시 Helper는 즉시 종료된다.
5. source/bundled 모드 모두 동일한 재기동 정책이 적용된다.
6. 기존 실행 경로(uv run, bundled binary)는 유지된다.
7. backoff는 1s → 2s → 4s → 8s → 16s(최대 5회 재시도)로 적용한다.
8. 최대 재시도 초과 시 로그를 남기고 UI 알림 없이 종료된다.
9. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Tasks / Subtasks
- [ ] backend 종료 감지 및 재기동 루프 추가 (AC: 1, 7)
  - [ ] 종료 이벤트/termination handler 도입
- [ ] Helper 종료 시 backend 정상 종료 보장 (AC: 2)
- [ ] 재기동 후 포트 로그/파싱 유지 확인 (AC: 3)
- [ ] 최대 재시도 초과 시 Helper 종료 처리 (AC: 4, 8)
- [ ] source/bundled 실행 경로 유지 확인 (AC: 5, 6)
- [ ] 수동 QA 수행 (AC: 9)

## Dev Notes
- `ProcessRunner`가 `Process`를 실행하므로 `terminationHandler`를 활용해 종료 감지를 추가할 수 있다.
- `HelperLifecycle`에서 backend 재기동 루프를 관리하는 구조가 자연스럽다.
- stderr 파싱(`Uvicorn running on ...`)을 통한 포트 추출 흐름은 재기동 후에도 유지해야 한다.

- 참고: `docs/architecture/source-tree.md#핵심-모듈과-역할`
