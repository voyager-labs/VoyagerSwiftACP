# Story 117.4 - UI 엔드포인트 탐지 정리 - Brownfield Addition

## User Story
As a 사용자,
I want UI가 backend 엔드포인트를 자동 탐지하길,
So that 동적 포트에서도 안정적으로 요청을 보낼 수 있다.

## Story Context

**Existing System Integration:**
- Integrates with: UI 앱의 backend 연결 지점 (TBD)
- Technology: SwiftUI + TCA, macOS 프로세스 탐지 유틸
- Follows pattern: 기존 DependencyKey 기반 클라이언트 구성
- Touch points: UI 네트워크/endpoint 구성 코드 (TBD), Helper 프로세스 이름 `Voyager Backend`

## Acceptance Criteria

**Functional Requirements:**
1. UI는 `pgrep -f "Voyager Backend"` + `lsof -n -P -a -iTCP -sTCP:LISTEN -p <PID>`로 endpoint를 구성한다.
2. `PUBLIC_BACKEND_PORT=0` 환경에서도 endpoint 탐지가 정상 동작한다.
3. backend 재기동 시 UI는 endpoint를 재탐지한다.
4. runtime config/BackendState 공유 로직은 제거된다.

**Integration Requirements:**
5. source/bundled 모두 `Voyager Backend` 프로세스명 탐지가 가능하다.
6. 기존 UI 흐름과 충돌하지 않는다.

**Quality Requirements:**
7. 탐지 실패 시 1초 간격으로 3회 자동 재시도 후 NSAlert를 표시한다.
8. NSAlert 메시지: "Cannot connect to Voyager Backend"
9. NSAlert 설명: "Voyager couldn't find a running backend. Please wait a few seconds and retry."
10. NSAlert 버튼: "Retry"(기본), "Quit"(보조). Retry 시 탐지를 즉시 재시도한다.
11. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Technical Notes
- **Integration Approach:** 프로세스 탐지 유틸을 클라이언트로 분리하고 UI에서 호출.
- **Existing Pattern Reference:** TCA DependencyKey 기반 클라이언트 패턴.
- **Key Constraints:** sandbox/권한 정책에 따라 `pgrep`/`lsof` 호출 실패 시 fallback 필요.
  자동 재시도는 알림 표시 전 3회로 제한한다.

## Risk and Compatibility Check

**Minimal Risk Assessment:**
- **Primary Risk:** 프로세스 탐지 실패로 backend 연결 불가.
- **Mitigation:** 재시도/backoff 및 명확한 오류 표시.
- **Rollback:** 기존 endpoint 구성 로직으로 복귀.

**Compatibility Verification:**
- [ ] No breaking changes to existing APIs
- [ ] UI changes follow existing design patterns
- [ ] Performance impact is negligible
