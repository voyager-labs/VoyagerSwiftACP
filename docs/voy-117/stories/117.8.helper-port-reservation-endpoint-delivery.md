# Story 117.8: Helper 포트 선점 및 endpoint 전달

## Status
Draft

## Story
**As a** 개발자/운영자,  
**I want** Helper가 백엔드 포트를 선점하고 메인 앱에 endpoint를 전달하길,  
**so that** UI가 polling 없이 안정적으로 backend에 연결할 수 있다.

## Story Context
- Epic 연계: VOY-117 Helper/Backend 생명주기 일관화 목표의 endpoint 전달 파트
- 선행/의존: Story 117.8 완료 후 Story 117.9 → 117.3 → 117.2 진행
- Story 117.4는 fallback 탐지 참고용이며, 본 스토리가 우선한다.

## Acceptance Criteria
1. Helper는 backend 실행 전에 빈 포트를 선점하고(`bind(0)`), `PUBLIC_BACKEND_PORT`로 주입한다.
2. Helper는 선점한 포트로 backend를 실행하고, `connect` 기반 검증 루프로 LISTEN 여부를 확인한다. (100~200ms 간격, 최대 10회)
3. 포트 검증 실패 시 Helper는 backend를 종료한다. (재시도 없음)
4. Helper는 endpoint 확정 시 `DistributedNotificationCenter`로 `host/port/url`을 전달한다. (알림 키: `Notification.Name.backendEndpointDidUpdate`)
5. 메인 앱은 앱 시작 시 observer를 등록하고, 수신 시 `PUBLIC_BACKEND_PORT`/`PUBLIC_BACKEND_URL`을 갱신한다.
6. 메인 앱은 알림 미수신(Helper 실행 후 2초 내 미수신) 시 기존 endpoint 탐지(`BackendEndpointClient`)를 fallback으로 유지한다.
7. source/bundled 모드 모두 동일한 방식으로 포트 선점/전달이 동작한다.
8. 실패 시 로그가 남고 UI는 프리즈되지 않는다.

## Dev Notes
- Helper 실행 진입점: `apps/macos/Voyager/VoyagerHelper/Infrastructure/ProcessRunner.swift`
- 포트 선점은 `socket/bind(0)/getsockname` 기반으로 단일 함수로 캡슐화한다.
- 포트 검증은 `connect` 기반으로 통일한다. (짧은 확인 루프, 최대 10회)
- 알림 키는 `Notification.Name.backendEndpointDidUpdate`로 SSOT화하고, payload는 `host/port/url`로 고정한다.
- 메인 앱 observer는 Helper 실행 이전에 등록되도록 `AppLifecycleFeature` 혹은 `AppDelegate`에서 설치한다.
- 기존 `BackendEndpointClient`의 polling은 fallback으로 유지한다.
- 참고: `docs/voy-117/stories/117.4.ui-endpoint-discovery.md#dev-notes` (fallback 탐지)
