# Story 117.3 - Backend 재기동 관리 강화 - Brownfield Addition

## User Story
As a 사용자,
I want backend가 중단되더라도 Helper가 복구하길,
So that Voyager 기능이 지속적으로 동작한다.

## Story Context

**Existing System Integration:**
- Integrates with: `HelperLifecycle`, `ProcessRunner`
- Technology: VoyagerHelper, FastAPI(uv), Dispatch/Process
- Follows pattern: Helper 내부에서 backend 프로세스 실행/종료 관리
- Touch points: `apps/macos/Voyager/VoyagerHelper/Infrastructure/HelperLifecycle.swift`,
  `apps/macos/Voyager/VoyagerHelper/Infrastructure/ProcessRunner.swift`,
  `apps/macos/Voyager/VoyagerHelper/VoyagerHelperApp.swift`

## Acceptance Criteria

**Functional Requirements:**
1. Helper는 backend 종료를 감지하고 backoff 정책에 따라 재기동을 시도한다.
2. Helper 종료 시 backend 프로세스는 정상 종료된다.
3. 재기동 후에도 포트 할당 로그/파싱이 정상 동작한다.
4. 최대 재시도 초과 시 Helper는 즉시 종료된다.

**Integration Requirements:**
4. source/bundled 모드 모두 동일한 재기동 정책이 적용된다.
5. 기존 실행 경로(uv run, bundled binary)는 유지된다.

**Quality Requirements:**
6. backoff는 1s → 2s → 4s → 8s → 16s(최대 5회 재시도)로 적용한다.
7. 최대 재시도 초과 시 로그를 남기고 UI 알림 없이 종료된다.
8. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Technical Notes
- **Integration Approach:** backend 프로세스 종료 이벤트를 감지하고 재기동 루프 추가.
- **Existing Pattern Reference:** `ProcessRunner.startIfNeeded()`와 stderr 파싱 흐름.
- **Key Constraints:** 재기동 시점에 포트 재탐지가 가능해야 함. 재기동 실패 시 Helper는 종료.

## Definition of Done

## Risk and Compatibility Check

**Minimal Risk Assessment:**
- **Primary Risk:** 재기동 실패 반복으로 리소스 과다 사용.
- **Mitigation:** backoff 적용 및 최대 재시도 제한.
- **Rollback:** backend 재기동 로직을 기존 동작으로 복귀.

**Compatibility Verification:**
- [ ] No breaking changes to existing APIs
- [ ] Database changes (if any) are additive only
- [ ] Performance impact is negligible
