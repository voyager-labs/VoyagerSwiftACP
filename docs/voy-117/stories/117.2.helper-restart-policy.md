# Story 117.2: Helper 종료 감지 및 재시작 정책

## Status
Deferred

## Story
**As a** 사용자,  
**I want** Helper가 비정상 종료되더라도 자동으로 복구되길,  
**so that** Voyager 사용 중 기능이 안정적으로 유지된다.

## Acceptance Criteria
1. Voyager 실행 중 Helper 종료 이벤트를 감지하면 backoff 정책에 따라 재실행한다.
2. backoff는 1s → 2s → 4s → 8s → 16s(최대 5회 재시도)로 적용한다.
3. 재시도 중에는 사용자에게 UI 알림을 노출하지 않고 로그만 남긴다.
4. 최대 재시도 초과 시 Voyager는 즉시 종료(Crash)된다.
5. Voyager 종료 시 Helper를 강제로 종료하지 않는다.
6. Helper 재실행은 중복 실행을 방지한다.
7. 기존 앱 종료 흐름과 충돌하지 않는다.
8. 재시도/종료 이벤트가 로그로 확인 가능하다.
9. 변경 전후 회귀 동작이 수동 QA로 확인된다.

## Tasks / Subtasks
- [ ] Helper 종료 이벤트 감지 루프에 backoff/재시도 상태 추가 (AC: 1, 2)
  - [ ] 재시도 카운트 및 최대 재시도 조건 정의
- [ ] 재시도 중 로그 처리만 유지 (AC: 3, 8)
- [ ] 최대 재시도 초과 시 즉시 종료 정책 반영 (AC: 4)
- [ ] 앱 종료 시 Helper 종료 로직 제거/무시 확인 (AC: 5, 7)
- [ ] 중복 실행 방지 확인 (AC: 6)
- [ ] 수동 QA 수행 (AC: 9)

## Dev Notes
- 보류: Story 117.4 완료 후 재개한다. 엔드포인트 탐지 확정 후 재시도 정책 QA를 진행한다.
- `AppLifecycleFeature`가 `helperAppClient.terminationEvents()`를 감시한다.
- `HelperAppClient`는 `NSWorkspace.didTerminateApplicationNotification` 기반으로 종료 이벤트를 제공한다.
- 재시도 정책은 `AppLifecycleFeature`의 감시 루프 내부에 상태로 유지하는 편이 단순하다.
- 즉시 종료(Crash) 정책은 앱 종료 방식(예: `NSApp.terminate(nil)` 또는 `exit`)을 명시해야 한다.
