# Story 117.10: Helper 재시작 감시(Endpoint 타임아웃 기반)

## Status
Ready

## Story
**As a** 사용자,
**I want** Helper가 의도치 않게 종료되면 메인 앱이 감지해 재실행하고,
**so that** Helper가 정상 기동하지 못할 경우 메인 앱도 종료되어 완전 재실행을 시도할 수 있다.

## Acceptance Criteria
1. Helper 종료 이벤트를 감지하면 메인 앱은 재실행을 시도한다.
2. Helper 시작 성공 기준은 `backendEndpointDidUpdate` 수신으로 정의한다.
3. Helper 시작 후 **해당 시도 타임아웃 내** `backendEndpointDidUpdate`를 수신하지 못하면 시작 실패로 간주한다.
4. 시작 실패 시 재시도 카운트를 증가하고 타임아웃을 3→5→8→13→21s(최대 5회)로 증가시킨다.
5. 재시도 간 backoff는 **2초로 고정**하며, 즉시 실패(Helper가 즉시 종료/실행 실패)에도 동일하게 적용한다.
6. 연속 실패 횟수가 최대치를 초과하면 `exit(EXIT_FAILURE)`로 메인 앱을 종료한다.
7. `backendEndpointDidUpdate`를 수신하면 재시도 카운트를 초기화한다.
8. 재시도 중 UI 알림은 노출하지 않고 로그만 남긴다.
9. Helper 중복 실행을 방지한다.
10. 앱 종료 시 모니터링 루프가 중단되어 재시작이 발생하지 않는다.
11. 재시도/타임아웃/종료 이벤트가 로그로 확인 가능하다.
12. 변경 전후 회귀 동작이 수동 QA로 확인된다.
13. 상태 확인은 **폴링 없이** 이벤트(`backendEndpointDidUpdate`) + 단일 타임아웃으로만 구현한다.

## Dev Notes
- Helper 종료 감지는 `DispatchSourceProcess(.exit)` 이벤트 기반으로 처리한다.
- 시작 성공은 `backendEndpointDidUpdate` 수신으로 판정하며, **폴링 없이** 타임아웃(3→5→8→13→21s)으로 실패를 구분한다.
- 재시도 루프는 **이벤트 대기 + 타임아웃**으로만 구성하고, 주기적 상태 체크(폴링)는 금지한다.
- 타임아웃이 발생하면 Helper가 실행 중이어도 “시작 실패”로 간주하고 재시도를 진행한다.
- 시작 실패 후 재시도 전에 중복 실행을 방지하도록 Helper 상태를 정리한다.
- 재시도 카운트는 **연속 실패** 기준으로 증가하고, 성공 이벤트 수신 시 초기화한다.
- DNC(`helperWillTerminate`)는 graceful 종료 메타데이터 보강용이며, 감지 자체는 exit 이벤트 기준이다.
- **정책 결정:** 타임아웃은 3→5→8→13→21s(피보나치)로 증가한다. (시도 횟수에 따라 기다림을 늘려 안정성 확보)
- **정책 결정:** 재시도 backoff는 2초로 고정하며, 즉시 실패에도 동일하게 적용한다.
- **정책 결정:** 타임아웃 합산 대기 시간은 약 50초, backoff 포함 총 대기 시간은 약 58초 이내로 제한한다.
- **정책 결정:** 최대 재시도 초과 시 `exit(EXIT_FAILURE)`로 앱을 종료해 완전 재실행 경로를 유도한다.
- `backendEndpointDidUpdate`는 Helper가 backend 기동 후 포트 검증 완료 시 발행한다. (참조: `docs/voy-117/stories/117.8.helper-port-reservation-endpoint-delivery.md`)
- 이벤트 payload는 `host`, `port`, `url` 중 하나 이상을 포함하며, 수신 시점을 성공 기준으로 삼는다. (정의: `apps/macos/Voyager/Shared/Notifications/BackendEndpointNotifications.swift`)
- 변경 대상(예상):
  - `apps/macos/Voyager/Voyager/App/Features/AppLifecycleFeature.swift`
  - `apps/macos/Voyager/Voyager/App/Clients/HelperAppClient.swift`
  - `apps/macos/Voyager/Voyager/App/Clients/BackendEndpointClient.swift`
- 참고: `docs/voy-117/epic.md#epic-goal`
- 참고: `docs/architecture/source-tree.md#핵심-모듈과-역할`

### Testing
#### 수동 QA 절차
- 준비
  1. Voyager 실행 후 Helper가 동작 중인지 확인한다.
  2. Helper PID를 확인한다. (Activity Monitor 또는 `pgrep -fl VoyagerHelper`)
- 시나리오 A: Helper 종료 → 재시작(backoff)
  1. Helper를 종료한다. (Activity Monitor Quit 또는 `kill -TERM <PID>`)
  2. 로그에 `attempt 1/5`로 시작하는 재시도 로그가 찍히는지 확인한다.
  3. 타임아웃이 3→5→8→13→21s로 증가하는지 확인한다.
  4. 각 재시도 사이 backoff가 2초로 고정되는지 확인한다.
- 시나리오 B: 시작 타임아웃 → 재시도
  1. Helper 시작 직후 `backendEndpointDidUpdate`가 첫 타임아웃(3초) 내 오지 않도록 유도한다.
     - 예: backend 포트 검증이 실패하도록 환경 변수를 임시 변경하거나, endpoint 전달 로직을 임시 차단한다.
  2. 첫 타임아웃(3초) 경과 후 시작 실패 로그와 재시도 카운트 증가가 발생하는지 확인한다.
- 시나리오 B-1: 즉시 실패 최소 대기
  1. Helper가 즉시 종료되도록 유도한다. (예: 실행 파일 경로 오류, 권한 문제)
  2. 다음 시도 전 최소 2초 대기가 로그로 확인되는지 확인한다.
- 시나리오 C: 최대 재시도 초과
  1. 시작 타임아웃을 연속으로 유발한다.
  2. 최대 재시도 초과 시 `exit(EXIT_FAILURE)`로 앱이 종료되는지 확인한다.
- 시나리오 D: 정상 기동 후 카운트 리셋
  1. 정상적으로 `backendEndpointDidUpdate`를 수신한다.
  2. 이후 Helper 종료 시 재시도 로그가 `attempt 1/5`로 리셋되는지 확인한다.
- 시나리오 E: 앱 종료 시 재시작 없음
  1. Voyager 앱을 정상 종료한다.
  2. 모니터링 루프가 중단되어 재시작 로그가 발생하지 않는지 확인한다.
- 공통 확인
  1. UI 알림이 표시되지 않는지 확인한다.
  2. 종료 이벤트/타임아웃/재시도 카운트 로그가 남는지 확인한다.
  3. Helper가 중복 실행되지 않는지 확인한다.
