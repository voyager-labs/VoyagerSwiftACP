# Story 117.5: BACKEND_MODE 기반 DB 경로 분리 및 관계 문서 정리

## Status
Draft

## Story
**As a** 개발자/운영자,  
**I want** BACKEND_MODE에 따라 DB 경로가 결정되도록,  
**so that** source/bundled 실행 방식에 맞는 DB 위치를 일관되게 사용할 수 있다.

## Acceptance Criteria
1. `BACKEND_MODE=source`일 때 DB 경로는 프로젝트 내 DB(`voyager.dev.db`)를 사용한다.
2. `BACKEND_MODE=bundled`일 때 DB 경로는 Application Support 경로를 사용한다.
3. `BACKEND_MODE`가 없을 경우 기존 `APP_ENV` 기반 경로 결정 로직으로 fallback 한다.
4. `BACKEND_MODE`는 Python 실행 경로와 DB 경로만 변경한다.
5. `APP_ENV`는 런타임 환경/시크릿/외부 클라이언트 설정에만 영향을 주도록 문서에 명시한다.
6. 문서의 오타(`BACKEND_MDOE`)를 `BACKEND_MODE`로 수정한다.
7. 문서에서 Target/Scheme/Configuration/APP_ENV/BACKEND_MODE 관계를 요약 표로 정리한다.
8. 문서에 `Voyager-*`가 `VoyagerHelper-*`를 실행한다는 관계를 명시한다.
9. source/bundled 각각에서 DB 경로가 기대값으로 설정되는지 확인한다.
10. 기존 앱/헬퍼 실행 흐름에 회귀가 없음을 수동 QA로 확인한다.

## Dev Notes
- `apps/backend/src/app/config/db/sqlite.yaml`은 `app.env` 기반 파일 맵을 사용 중이다.
- `apps/backend/src/app/config/config.yaml`은 기본 `env: dev`를 사용하며, `APP_ENV`로 전환된다.
- `apps/backend/src/app/config/__init__.py`의 `get_db_config()`에서 DB 경로가 확정된다.
- `BACKEND_MODE`는 DB 경로/실행 경로에만 영향을 주도록 범위를 제한한다.
- `APP_ENV`는 런타임 환경/시크릿/외부 클라이언트 설정에만 영향을 주도록 정리한다.
- 참고: `docs/voy-117/epic.md#epic-goal`
- 참고: `docs/architecture/build-schemes-and-environments.md#스킴과-환경의-매핑`
- 참고: `docs/architecture/development-and-deployment.md#스킴--빌드-설정과-실행-모드`
