# Story 117.5: BACKEND_MODE 기반 DB 경로 분리 및 관계 문서 정리

## Status
Done

## Story
**As a** 개발자/운영자,  
**I want** BACKEND_MODE에 따라 DB 경로가 `.env.source`/`.env.bundled`로 명확히 분리되길,  
**so that** source/bundled 실행 환경 모두에서 일관된 DB 위치를 보장할 수 있다.

## Acceptance Criteria
1. `BACKEND_MODE=source`일 때 DB 경로는 `.env.source`의 `PUBLIC_SQLITE_*` 조합으로 결정된다.
2. `BACKEND_MODE=bundled`일 때 DB 경로는 `.env.bundled`의 `PUBLIC_SQLITE_*` 조합으로 결정된다.
3. `BACKEND_MODE` 미설정 시 기본값은 `source`이며, `.env.source`가 우선 로드된다.
4. `APP_ENV`는 `.env.{APP_ENV}`를 로드하되, DB 경로는 `BACKEND_MODE` 기준 값을 우선 사용한다(override=false).
5. `BACKEND_MODE`는 Python 실행 경로와 DB 경로만 변경한다.
6. `APP_ENV`는 런타임 환경/시크릿/외부 클라이언트 설정에만 영향을 주도록 문서에 명시한다.
7. 문서의 오타(`BACKEND_MDOE`)를 `BACKEND_MODE`로 수정한다.
8. 문서에서 Target/Scheme/Configuration/APP_ENV/BACKEND_MODE 관계를 요약 표로 정리한다.
9. 문서에 `Voyager-*`가 `VoyagerHelper-*`를 실행한다는 관계를 명시한다.
10. source/bundled 각각에서 DB 경로가 기대값으로 설정되는지 확인한다.
11. 기존 앱/헬퍼 실행 흐름에 회귀가 없음을 수동 QA로 확인한다.

## Dev Notes
- 설정 로더: `apps/backend/src/app/config.py` (Hydra 제거 완료).
- 로딩 순서: 프로세스 env → `.env.{BACKEND_MODE}` → `.env.{APP_ENV}` (override=false).
- DB 경로는 `PUBLIC_SQLITE_PROTOCOL` + `PUBLIC_SQLITE_FILE_LOCATION` + `PUBLIC_SQLITE_FILE_NAME` 조합으로 결정된다.
  - 예: `.env.source`는 프로젝트 루트 `voyager.dev.db`, `.env.bundled`는 `~/Library/Application Support/Voyager/voyager.db`.
- `BACKEND_MODE` 기본값은 `source`, `APP_ENV` 기본값은 `dev`.
- `BACKEND_MODE`는 DB 경로/실행 경로에만 영향, `APP_ENV`는 환경/시크릿/외부 클라이언트 설정에만 영향.
- 참고: `docs/voy-117/epic.md#epic-goal`
- 참고: `docs/architecture/build-schemes-and-environments.md#스킴과-환경의-매핑`
- 참고: `docs/architecture/development-and-deployment.md#스킴--빌드-설정과-실행-모드`
