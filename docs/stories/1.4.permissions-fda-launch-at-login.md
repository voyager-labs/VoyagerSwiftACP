# Story 1.4: Permissions Step (Full Disk Access) + Launch at Login (Optional)

## Status

Done

## Story

**As a** 신규 사용자,  
**I want** `Permissions` 단계에서 `Full Disk Access` 권한을 명확히 안내/설정하고, (선택) 로그인 시 자동 실행을 토글할 수 있게,  
**so that** 핵심 기능이 필요한 권한 없이 “겉보기만 동작하는” 상태로 들어가지 않으면서도 편의 설정은 최소 마찰로 선택할 수 있다.

## Acceptance Criteria

1. `Permissions` 스텝에서 `Full Disk Access`의 현재 상태(`Granted` / `Needs Action` / `Denied` / `Unknown`)가 표시된다.  
2. FDA가 `Granted`일 때만 `Next`가 활성화된다.  
3. FDA 승인 후 백그라운드 인덱싱이 `/`부터 시작된다. 인덱싱은 온보딩 진행을 막지 않는다.  
4. 사용자는 FDA에 대해 “다음 행동”(설정 열기/가이드)을 같은 화면에서 수행할 수 있으며, 딥링크 실패 시 수동 경로가 안내된다.  
5. `Files & Folders` 섹션에 버튼이 제공되며, 한 번의 흐름에서 `Desktop`/`Documents`/`Downloads` 권한을 요청할 수 있다. 이 권한은 `Next` 활성화 조건에 영향을 주지 않는다.  
6. (선택) `Launch at Login` 토글이 제공되며 On/Off를 전환할 수 있다. 이 토글은 `Next` 활성화 조건에 영향을 주지 않는다.  
7. FDA가 `Granted`가 아닐 때 `Next` 비활성화 이유/안내가 화면에 노출된다.

- Implementation detail to clarify early:

  - 앱 복귀 시(`NSApplication.didBecomeActiveNotification`) FDA 상태를 재확인한다.
  - 딥링크 실패 시 수동 경로 안내 문구를 항상 표시한다.
  - `Files & Folders` 권한은 FDA와 별개이며, `Next` 게이팅에 영향을 주지 않는다.

### UX Decisions (Draft)

- 상태 라벨(영문): `Granted` / `Needs Action` / `Denied` / `Unknown` (상태 라벨은 영문 그대로 노출)
- `Granted` 상태 메시지: “Full Disk Access is granted. You can continue.”(Full Disk Access 권한이 허용되었습니다. 계속 진행할 수 있어요.)
- `Needs Action` 상태 메시지: “Full Disk Access is required to continue. Please enable it in System Settings.”(계속 진행하려면 Full Disk Access 권한이 필요합니다. 시스템 설정에서 허용해 주세요.)
- `Denied` 상태 메시지: “Full Disk Access was denied. You can change this in System Settings.”(Full Disk Access 권한이 거부되었습니다. 시스템 설정에서 변경할 수 있어요.)
- `Unknown` 상태 메시지: “We couldn’t confirm your Full Disk Access status yet.”(Full Disk Access 상태를 아직 확인할 수 없어요.)
- FDA 상태 규칙:
  - `Granted`: 권한이 허용된 상태(사용자가 접근을 승인한 상태).
  - `Needs Action`: 아직 허용되지 않았고, 사용자가 허용할 수 있는 상태(초기/미허용).
  - `Denied`: 사용자가 명시적으로 거부했거나 보안 정책상 차단된 상태.
  - `Unknown`: 상태 확인 실패/지연 등으로 판정할 수 없는 상태.
- `Next` 비활성화 안내: “Full Disk Access is required to continue.”(계속하려면 Full Disk Access 권한이 필요합니다.)
- FDA CTA 라벨: “Open System Settings”(시스템 설정 열기)
- FDA 경로 안내: “System Settings > Privacy & Security > Full Disk Access”(시스템 설정 > 개인정보 보호 및 보안 > 전체 디스크 접근)
- FDA CTA 동작:
  - `Granted`일 때는 CTA를 숨기고 상태 메시지만 노출한다.
  - `Needs Action`/`Denied`/`Unknown`일 때 CTA를 노출한다.
- `Next` 비활성화 안내 위치: `Next` 버튼 바로 아래에 보조 문구로 노출한다.
- 섹션 타이틀: “Files & Folders”(파일 및 폴더)
- 설명 문구: “Allow access to Desktop, Documents, and Downloads.”(Desktop, Documents, Downloads 폴더에 접근을 허용합니다.)
- CTA 라벨: “Grant Access”(접근 허용)
- 성공 안내: “Access granted for Desktop, Documents, and Downloads.”(Desktop, Documents, Downloads 권한이 허용되었습니다.)
- 부분 성공 안내: “Some folders weren’t granted. You can retry or grant them later in System Settings.”(일부 폴더 권한이 허용되지 않았어요. 다시 시도하거나 시스템 설정에서 나중에 허용할 수 있어요.)
- 취소/미응답 안내: “You can grant access later in System Settings.”(시스템 설정에서 나중에 권한을 허용할 수 있어요.)
- Files & Folders CTA 동작:
  - 한 번의 흐름에서 세 폴더를 요청한다(가능 시 multi-select, 불가 시 순차 요청 + 진행 안내).
  - 순차 요청일 때 진행 안내: “Grant access (1 of 3)”(접근 허용 (1/3)) 형식으로 표시한다.
  - 요청 결과에 따라 각 폴더 상태를 리스트로 요약한다(예: Desktop: Granted, Documents: Not Granted).
- Files & Folders 규칙:
  - 상태: `Granted` / `Partial` / `Not Granted`
  - `Granted`: Desktop/ Documents/ Downloads 모두 허용됨
  - `Partial`: 1개 이상 허용되었으나 전부는 아님
  - `Not Granted`: 모두 미허용 또는 사용자 취소
- Launch at Login 라벨: “Launch at Login”(로그인 시 자동 실행)
- Launch at Login 설명: “Start Voyager automatically when you log in.”(로그인하면 Voyager가 자동으로 시작됩니다.)
- Launch at Login 실패 안내: “We couldn’t update your Login Items. You can manage this in System Settings.”(로그인 항목을 업데이트하지 못했어요. 시스템 설정에서 관리할 수 있어요.)
- Launch at Login 경로 안내: “System Settings > Login Items”(시스템 설정 > 로그인 항목)
- 인덱싱 안내 문구: “Indexing is running in the background from `/`.”(인덱싱은 `/`부터 백그라운드에서 실행 중입니다.)
- Integration note:
  - 인덱싱 프리셋(범위 설정) UI는 OBT에서 제공한다. CBT에서는 프리뷰만 제공한다.
  - 초기 인덱싱(`POST /index`, 대상 `/`)은 `Permissions` 스텝에서 시작되며 백그라운드로 계속 실행된다.
    - TODO(VOY-117, VOY-88): 인덱싱 포트 연동 및 인덱싱 엔드포인트 완료 후 실제 트리거 연결.
  - (결정) 실제 인덱싱 실행 주체는 **backend 바이너리**이며, `VoyagerHelper`가 이를 실행한다. FDA는 프로세스 단위 권한이므로 Voyager가 FDA를 “받아서 위임”할 수 없다. 연동 작업에서 `VoyagerHelper`/실행 체인의 FDA 적용을 검증한다.

### Testing

- Key scenarios:
  - FDA granted → Next enabled
  - FDA missing/denied → Next disabled + clear explanation + settings guidance
  - Files & Folders granted → inline success state
  - Files & Folders partial/cancel → inline guidance without blocking Next
  - Launch at Login toggle on/off succeeds → state updates
  - Launch at Login toggle fails → inline guidance shown, onboarding not blocked
