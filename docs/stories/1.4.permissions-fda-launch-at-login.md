# Story 1.4: Permissions Step (Full Disk Access) + Launch at Login (Optional)

## Status

Draft

## Story

**As a** 신규 사용자,  
**I want** `Permissions` 단계에서 `Full Disk Access` 권한을 명확히 안내/설정하고, (선택) 로그인 시 자동 실행을 토글할 수 있게,  
**so that** 핵심 기능이 필요한 권한 없이 “겉보기만 동작하는” 상태로 들어가지 않으면서도 편의 설정은 최소 마찰로 선택할 수 있다.

## Acceptance Criteria

1. `Permissions` 스텝에서 `Full Disk Access`의 현재 상태가 표시된다.  
2. FDA가 `Granted`일 때만 `Next`가 활성화된다.  
3. (플레이스홀더) FDA 승인 후 백그라운드 인덱싱이 `/`부터 실행될 예정임을 안내한다. 이 안내는 온보딩 진행을 막지 않는다.  
4. 사용자는 FDA에 대해 “다음 행동”(설정 열기/가이드)을 같은 화면에서 수행할 수 있다.  
5. (선택) `Launch at Login` 토글이 제공되며 On/Off를 전환할 수 있다. 이 토글은 `Next` 활성화 조건에 영향을 주지 않는다.  
6. 상단 요약 뱃지(`FDA`)가 상태에 맞게 갱신된다.

## Dev Notes

- Depends on: Story 1.2 (step navigation + state machine)
- UX/AC source:
  - `docs/frontend/onboarding-window-spec.md#permission-full-disk-access`
  - `docs/frontend/onboarding-window-spec.md#acceptance-criteria-locked-for-voy-111`
- TCA architecture notes:
  - Implement this as `PermissionsFeature` (child reducer). `OnboardingFeature` remains the single owner of cross-step navigation and `Next` gating.
  - Prefer dependency-injected side effects (open System Settings, toggle launch-at-login) to keep the reducer testable.
- Implementation detail to clarify early:
  - FDA 상태 감지/리프레시 전략이 “Next 활성화” 요구사항을 만족해야 한다.
- Integration note:
  - 인덱싱 프리셋(범위 설정) UI는 OBT에서 제공한다. CBT에서는 프리뷰만 제공한다.
  - 초기 인덱싱(`POST /index`, 대상 `/`)은 CBT 범위이지만, VOY-111에서는 실제 호출은 하지 않고 플레이스홀더만 둔다.
  - (결정) 실제 인덱싱 실행 주체는 **backend 바이너리**이며, `VoyagerHelper`가 이를 실행한다. FDA는 프로세스 단위 권한이므로 Voyager가 FDA를 “받아서 위임”할 수 없다. 연동 작업에서 `VoyagerHelper`/실행 체인의 FDA 적용을 검증한다.

### Testing

- Key scenarios:
  - FDA granted → Next enabled
  - FDA missing/denied → Next disabled + clear explanation + settings guidance
  - Launch at Login toggle on/off succeeds → state updates
  - Launch at Login toggle fails → inline guidance shown, onboarding not blocked
