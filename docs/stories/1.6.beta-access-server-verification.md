# Story 1.6: Beta Access Step (Server Verification)

## Status

Draft

## Story

**As a** 베타 사용자,  
**I want** `Beta Access` 단계에서 이메일/토큰을 서버로 검증하여 베타 활성 상태를 확인하고,  
**so that** 베타 접근이 확인되기 전에는 다음 단계로 진행하지 않게 하여 품질/정책을 준수할 수 있다.

## Acceptance Criteria

1. 서버 검증은 `https://gateway.voyager.fm`을 베이스로 하며, 이메일/토큰을 포함한 요청을 보낸다(엔드포인트/스키마는 별도 정의).
2. 응답은 `Active` / `Not Active` / `Check failed` 상태로 매핑된다.
3. `Not Active` 사유는 계약 기반으로 가이드가 노출된다(이메일/토큰 불일치, 미입력, 해당 이메일에 이미 토큰 등록 등).
4. `Active`가 되기 전까지 `Next`는 비활성화되고, `Active`가 되면 상단 요약 뱃지(`Beta`)가 `Granted`로 갱신된다.
5. Mock-only 시나리오 순환은 제거되고, 실제 서버 응답이 상태를 결정한다.

## Tasks / Subtasks

- [ ] Define beta access verification contract (AC: 1–3)
  - [ ] Decide endpoint path + HTTP method + request/response schema
  - [ ] Define error mapping: timeout/offline/5xx → `Check failed`
  - [ ] Define Not Active reason codes (mismatch, missing input, token already registered)
- [ ] Implement `BetaAccessClient` live networking (AC: 1–3)
  - [ ] Call gateway base URL and parse contract response
  - [ ] Keep mock/test variants for previews/tests
- [ ] Update `BetaAccessFeature` to use live response (AC: 2–5)
  - [ ] Preserve cancel/retry behavior
  - [ ] Remove mock scenario rotation
- [ ] Tests (AC: 1–5)
  - [ ] Unit tests for response mapping + gating using `TestStore`

## Dev Notes

- Depends on: Story 1.3 (mock verification + UI + gating)
- Gateway base URL: `https://gateway.voyager.fm`
- Backend reference (testers table):
  ```sql
  create table if not exists public.testers (
    tester_id text primary key,
    email citext not null unique,
    cohort text not null,
    status text not null default 'active' check (status in ('active', 'disabled')),
    created_at timestamptz not null default now(),
    disabled_at timestamptz,
    notes text,
    token_hash text,
    token_label text,
    token_created_at timestamptz,
    token_revoked_at timestamptz,
    token_expires_at timestamptz
  );
  ```
- **BLOCKER / Required Input:** 엔드포인트 경로와 응답 스키마가 정의되지 않았다. 계약 확정 전에는 착수하지 않는다.

### Testing

- Unit tests should simulate:
  - Active → Next enabled
  - Not Active → Next disabled + guidance
  - Check failed + Retry loop
