# Story 1.1: Onboarding Window Skeleton & Launch Routing

## Status

Done

## Story

**As a** 신규 사용자,  
**I want** 앱 실행 시 온보딩이 필요한 경우 `Onboarding Window`만 표시되고 `File Manager Window`가 생성되지 않도록,  
**so that** 필수 설정(베타/권한/프리셋)을 완료하기 전에는 핵심 기능을 사용하지 않게 하여 품질을 보장할 수 있다.

## Acceptance Criteria

1. 앱 실행 직후 온보딩이 필요한 상태라면 `Onboarding Window`만 표시되고 `File Manager Window`는 생성되지 않는다.  
2. 온보딩이 필요 없으면 기존처럼 `File Manager Window`가 열린다.  
3. `Onboarding Window`는 파일 관리자 탭 그룹에 합쳐지지 않는 독립 윈도우로 표시된다(탭/탭바 정책 분리).  
4. 앱을 다시 활성화했을 때(예: Dock 아이콘 클릭) 온보딩이 필요한 상태라면 `Onboarding Window`가 다시 전면에 표시된다.  
5. 온보딩 UI는 최소 스켈레톤(placeholder)로 표시되어 “온보딩 플로우 진입”이 육안으로 확인 가능하다.

## Dev Notes

- Depends on: None (Epic 1 — Onboarding의 첫 스토리)
- UX/AC source: `docs/frontend/onboarding-window-spec.md#acceptance-criteria-locked-for-voy-111`
- Existing launch behavior:
  - `apps/macos/Voyager/Voyager/App/AppDelegate.swift` currently calls `createNewWindow()` in `applicationDidFinishLaunching`.
  - `createNewWindow()` creates `FileManagerWindowController` which tabs into the file-manager group by default.
- Window responsibilities:
  - File manager: `apps/macos/Voyager/Voyager/App/FileManagerWindowController.swift`
  - Launch + window orchestration: `apps/macos/Voyager/Voyager/App/AppDelegate.swift`
- TCA architecture requirement:
  - Onboarding UI should be driven by a TCA store (`StoreOf<OnboardingFeature>`), consistent with other domains (e.g., `FileManagerFeature`, `FSItemsFeature`).
  - Store ownership pattern can follow `apps/macos/Voyager/Voyager/App/FileManagerWindowController.swift` (creates a `Store(initialState:) { Feature() }` and hosts SwiftUI).
- This story intentionally does **not** implement full step navigation/persistence (see Story 1.2).

### Testing

- Unit tests (optional in this story): extract gate decision into a pure function/service and test in `apps/macos/Voyager/VoyagerTests`.
- If a reducer-level gate is introduced, prefer TCA `TestStore` tests for “required vs not required” routing decisions.
- Manual QA checklist:
  - Fresh state: onboarding window only.
  - Completed state: file manager window opens.
  - Re-activate app: onboarding stays accessible/front.
