# Gate 0.5: Source Availability

Gate 0 매니페스트에 등장한 모든 참조 대상이 실제로 존재하는지 확인한다.

깊은 리뷰에 들어가기 전에 끊어진 링크, 누락된 파일, 없는 참조를 먼저 잡는 게이트.

## Input

Gate 0에서 전달받은 데이터:

| Data | Description |
|---|---|
| `interaction_ids[]` | FI에 등록된 전체 interaction_id |
| `spec_file_map{}` | interaction_id → 스펙 파일 경로 |
| `missing_specs[]` | 스펙 파일이 없는 interaction_id |
| `category_key` | 오디트 대상 카테고리 |

## Procedure

### 1. 스펙 파일 존재 여부 (missing specs)

`missing_specs`에 있는 각 interaction_id에 대해:

- 해당 interaction_id로 스펙 파일을 생성할지 결정
- `status = deprecated`인 interaction은 `out_of_scope` 처리 가능
- 그 외의 경우, 빈 스펙 스켈레톤을 생성하거나 작성 예정으로 표시

### 2. FI row 존재 확인

각 스펙 파일의 frontmatter `interaction_id`가 INTERACTIONS TSV에 실제로 있는지 확인.

```bash
# 각 스펙의 interaction_id가 FI에 있는지 grep
grep "<interaction_id>" PRODUCT/04_FEATURE_INVENTORY/INTERACTIONS/data.tsv
```

### 3. Contract 파일 존재 확인

```bash
ls PRODUCT/05_FEATURE_SPECS/<category>/contracts/*.toml
```

카테고리에 contract가 아예 없으면 NP. 최소 하나의 `.toml` 파일이 있어야 한다.

### 4. Flow 파일 존재 확인

```bash
ls PRODUCT/05_FEATURE_SPECS/<category>/flows/*.md
```

카테고리에 flow가 아예 없으면 경고(WARN). contract가 있는데 flow가 없으면 NP.

### 5. Source 섹션 링크 검증

각 스펙 파일의 `## Source` 섹션에서 상대경로 링크를 추출해 실제 파일이 있는지 확인.

검증 대상:
- contract 파일 경로
- flow 파일 경로
- IA WINDOW_STRUCTURE 참조
- 기타 상대경로 참조

### 6. IA WINDOW_STRUCTURE 참조 확인

스펙 frontmatter의 `related_region` 값이 `PRODUCT/03_INFORMATION_ARCHITECTURE/WINDOW_STRUCTURE/data.tsv`에
존재하는지 확인.

```bash
# related_region 값이 WINDOW_STRUCTURE에 있는지
grep "<structure_key>" PRODUCT/03_INFORMATION_ARCHITECTURE/WINDOW_STRUCTURE/data.tsv
```

## P/NP Criteria

### PASS

- 모든 `interaction_id`에 스펙 파일이 존재 (또는 `out_of_scope`로 명시적 제외)
- 모든 스펙 파일의 `interaction_id`가 FI에 등록되어 있음
- 카테고리 contract 파일이 최소 1개 존재
- contract가 있는 카테고리에 flow 파일이 최소 1개 존재
- 모든 Source 섹션 상대경로가 유효
- 모든 `related_region` 참조가 WINDOW_STRUCTURE에 존재

### NOT PASS

- interaction_id가 FI에 없는 스펙 파일이 존재
- contract 파일이 아예 없음
- contract가 있는데 flow가 없음
- Source 섹션에 끊어진 링크가 있음
- `related_region`이 WINDOW_STRUCTURE에 없음
- 필수 스펙 파일이 누락되어 있고 `out_of_scope` 처리도 안 됨

## Fix Protocol

### 누락된 스펙 파일

1. `feature-inventory-checker` 스킬로 FI row를 먼저 확인
2. FI row가 있으면 `feature-spec-author` 스킬로 스펙 스켈레톤 생성
3. FI row가 없으면 FI row를 먼저 추가해야 함. 이슈로 기록하고 `out_of_scope` 처리

### 끊어진 Source 링크

1. 링크가 가리키는 파일이 존재하는 경로를 찾는다
2. 파일이 이동된 경우: 링크를 올바른 경로로 수정
3. 파일이 없는 경우: 파일을 생성하거나 링크를 제거

### 없는 contract / flow

1. contract가 없으면 카테고리 계약 정의가 선행되어야 함
2. `feature-spec-author` 스킬 참조하여 contract 초안 작성
3. flow는 contract가 확정된 후 작성

### WINDOW_STRUCTURE 참조 불일치

1. `information-architecture-author` 스킬로 WINDOW_STRUCTURE 확인
2. 스펙의 `related_region`을 올바른 키로 수정
3. WINDOW_STRUCTURE 자체에 키가 없으면 키 추가 필요

## Commit Format

```
audit(<CATEGORY>): Gate 0.5 — source availability verified
```

## Output

1. **Availability report**: 각 참조 대상의 존재 여부 테이블
2. **Fixes applied**: 수정한 내역 (생성한 파일, 수정한 링크 등)
3. **Gate 0.5 result**: P or NP
4. **Audit matrix**: Gate 0.5 컬럼 업데이트

다음 게이트로 전달하는 데이터:
- `verified_specs[]`: 모든 참조가 검증된 스펙 파일 목록
- `verified_contracts[]`: 검증된 contract 파일 목록
- `verified_flows[]`: 검증된 flow 파일 목록
