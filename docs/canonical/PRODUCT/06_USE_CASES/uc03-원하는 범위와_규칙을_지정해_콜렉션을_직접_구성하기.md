# **UC03. 원하는 범위와 규칙을 지정해 콜렉션을 직접 구성하기**

## [USE_CASES](index.md)\[PREV: UC02. 현재 디렉토리의 엔트리를 이름 변경∙삭제 등 관리하기](uc02-현재*디렉토리의*엔트리를*이름*변경*삭제*등\_관리하기.md) | [NEXT: UC04. 원하는 엔트리 묶음을 채팅으로 찾아보기](mvp.md)

1. ## **Summary**
    1. ### **One-line Definition**

- 여러 디렉토리와 엔트리 속성 조건을 직접 편집하거나, 자연어 쿼리를 입력∙제출하여 규칙 기반 콜렉션을
  구성하고, 이를 재사용 가능한 가상 폴더 뷰를 구성하는 흐름 2. ### **Purpose**

- 개별 디렉토리 단위로 브라우징·정리하던 사용자가, 매번 브라우징이나 수동 정리 없이도 속성 기반 조건
  규칙만으로 항상 최신 상태의 엔트리 집합을 직접 정의할 수 있도록 하기 위함
- 사용자가 프로퍼티 컨디션을 일일이 설정하지 않아도, 자연어 1문장 제출만으로 초기 필터를 빠르게
  구성할 수 있도록 하기 위함
- 생성된 조건을 수동 조건 편집으로 보정해, 최종적으로 신뢰 가능한 규칙 기반 콜렉션을 만들 수 있도록
  하기 위함

2. ## **Scope**
    1. ### **In-Scope**

- 페이지 상단에서 콜렉션 필터 편집기를 통해 현재 뷰를 규칙 기반 콜렉션 뷰로 전환하는 동작
- 파일명, 경로, 타입, 날짜, 태그, 커스텀 프로퍼티 등 엔트리 프로퍼티 컨디션을 조합해 콜렉션 규칙을
  직접 구성하는 동작
- 조건을 구성하는 입력 방식
    - 수동 편집 기반: 조건을 추가·수정·삭제하며 규칙을 다듬는 방식
    - 쿼리 기반: 현재 필터를 제출 시점에 생성된 구조화된 필터로 일괄 교체
- 현재 필터 상태를 새 콜렉션으로 저장하거나, 기존 콜렉션의 규칙 변경을 저장 또는 폐기하는 동작 2. ### **Out-of-Scope**

- 챗 패인에서 자연어로 조건을 설명하고, 시스템이 콜렉션 규칙을 구성·수정·저장까지 수행하는 플로우
    - 예: “최근 3개월 피치덱만 모아줘”, “이번 달 인보이스만 자동으로 콜렉션 저장해줘” 같은 요청을
      채팅으로 입력하는 경우\
      → UC04에서 다룸
- 콜렉션 결과에 대해 직접 정리·편집을 수행하는 플로우
    - 이름 변경, 이동, 삭제, 태그/메타데이터 변경 등 구조·메타데이터 변경 작업 자체\
      → UC02에서 다룸
- 전역 스토리지 수준에서 콜렉션 규칙을 이용해 자동 이동·삭제·아카이브를 수행하는 주기적/백그라운드
  정리 플로우
    - 로그인 시 자동 실행, 주기 실행, 조건 충족 시 트리거 자동 실행 등 사용자가 명시적으로 요청하지
      않은 전역 자동화
- 콜렉션 공유, 팀 단위 권한 관리 등 멀티 유저 협업 기능

3. ## **Flow**
    1. ### **Representative scenario**

- 사용자는 특정 작업과 관련된 파일을 찾고 있는데, 필요한 엔트리가 여러 디렉토리에 흩어져 있어 폴더
  구조를 바꾸지 않고 한 번에 모아 보고 싶다.
- 페이지 상단에서 콜렉션 필터 편집기를 열고, 이번 작업에 해당하는 디렉토리 범위를 스코프로 지정한다.
- 필터 쿼리에 자연어로 원하는 범위를 입력해 제출하면, 시스템이 구조화 필터로 생성하고 현재 필터를
  해당 생성본으로 일괄 교체해 적용한다
- 결과를 확인하면서 생성된 조건을 일부 수정하거나 추가해 규칙을 안정화한다.
- 만족스러운 구성이 되면 현재 스코프·조건을 콜렉션으로 저장해, 이후에도 같은 규칙 기반 뷰를
  재사용한다.

2. ### **Variations**

- Variation A: 필터 쿼리 없이 조건을 직접 추가해 필터를 조정
    - 사용자는 자연어 입력 없이, 조건을 하나씩 추가하고(프로퍼티/연산자/값) 필요한 엔트리만 남도록
      조정한다.
    - 결과를 보며 조건을 반복적으로 수정·삭제하고, 만족스러운 상태가 되면 저장하거나 임시 필터로만
      유지한다.
- Variation B: 현재 디렉토리 단일 스코프에서 콜렉션 구성
    - 사용자는 스코프를 확장하지 않고, 현재 디렉토리만 대상으로 조건을 추가·수정하며 결과를 좁혀 간다.
    - 결과가 의도에 맞으면 콜렉션으로 저장하거나, 필요 시 저장 없이 임시 필터로만 사용한다.
- Variation C: 여러 디렉토리를 스코프로 묶고 조건으로 정제
    - 사용자는 관련 디렉토리 몇 개를 스코프에 포함해 대상 범위를 먼저 확보한다.
    - 이후 타입, 날짜, 태그, 커스텀 프로퍼티 등 조건을 조합해 노이즈를 제거한다.
- Variation D: 저장된 콜렉션을 열고 조건을 미세 조정
    - 사용자는 기존 콜렉션을 출발점으로 삼아 일부 조건만 수정·추가·삭제한다.
    - 변경 결과를 비교하면서 최종 구성을 저장해 최신 규칙으로 갱신한다.
- Variation E: 기존 콜렉션에서 분기해 새 콜렉션 만들기
    - 사용자는 기존 콜렉션의 규칙을 일부 변경하되, 원본을 보존하기 위해 “새 콜렉션으로 저장” 흐름을
      선택한다.
    - 유사 목적의 파생 콜렉션을 빠르게 확보한다.
- Variation F: Undo/Redo로 여러 조건 조합을 비교
    - 사용자는 조건을 단계적으로 수정해 보며 결과를 비교한다.
    - 되돌리기/다시하기로 후보 조합들을 왕복한 뒤, 가장 적합한 상태를 저장한다.
- Variation G: 기존 콜렉션에서 분기해 새 콜렉션 만들기
    - 사용자는 기존 콜렉션의 규칙을 일부 변경하되, 원본을 덮어쓰지 않고 새 콜렉션으로 저장한다.
    - 원본은 유지하고, 유사 목적의 파생 콜렉션을 별도로 확보한다.
    3. ### **Exceptions**

- Zero result
    - 현재 스코프·조건 조합으로 일치하는 entry가 없는 경우, 빈 결과를 정상 상태로 표시한다.
    - 사용자가 조건을 완화할 수 있도록 최소 힌트를 제공한다.
- 인덱싱 미완료 범위 포함
    - 스코프에 인덱싱이 완료되지 않은 경로가 포함되면, 결과가 불완전할 수 있음을 표시한다.
    - 인덱싱 진행에 따라 결과가 갱신될 수 있음을 안내한다.
- Permission error
    - 스코프 내 일부 경로/entry에 접근 권한이 없으면, 접근 가능한 범위만으로 결과를 구성한다.
    - 제외된 범위와 원인이 권한 문제임을 확인할 수 있게 한다.
- 연결 해제된 스토리지/경로 포함
    - 외장/네트워크 스토리지 등 연결 상태 문제로 일부 스코프가 접근 불가하면 “연결 필요” 상태로
      표시한다.
    - 연결이 복구되면 결과를 다시 계산해 갱신한다.
- 유효하지 않은 조건 값 또는 타입 불일치
    - 프로퍼티 타입과 값/연산자가 맞지 않거나 값이 유효하지 않으면, 해당 조건을 오류 상태로 표시하고
      적용을 제한한다.
    - 사용자가 조건을 수정해 유효 상태로 복구할 수 있게 한다.
- 결과가 너무 많거나 계산이 오래 걸리는 경우
    - 처리 중 상태를 표시하고, 필요 시 일부 결과를 우선 표시할 수 있다.
    - 사용자가 스코프를 줄이거나 조건을 추가해 결과를 축소하도록 안내한다.
- Undo/Redo 불가 상태
    - 페이지 전환, 콜렉션 재로드, 세션 종료 등으로 편집 히스토리가 초기화되면 더 이상 Undo/Redo가
      불가함을 안내한다.
    - 필요하면 저장된 콜렉션을 다시 열어 기준 상태에서 재편집하도록 유도한다.
- 저장 실패
    - 로컬 DB/스토리지 오류 등으로 저장이 실패하면, 현재 편집 상태(미저장 변경)는 유지한다.
    - 실패 사유와 재시도 가능 경로를 제공한다.
- 콜렉션 로드 실패
    - 콜렉션 정의가 손상되었거나 필요한 데이터가 누락되어 로드가 실패하면 실패를 안내한다.
    - 가능한 경우 대체 경로(목록에서 재선택 등)를 제공하고, 화면 상태는 일관되게 유지한다.
