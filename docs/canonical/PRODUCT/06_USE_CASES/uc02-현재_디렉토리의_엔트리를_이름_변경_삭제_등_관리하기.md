# **UC02. 현재 디렉토리의 엔트리를 이름 변경∙삭제 등 관리하기**

## [USE_CASES](index.md)\[PREV: UC01. 디렉토리를 브라우징하며 필요한 엔트리 열기](uc01-디렉토리를*브라우징하며*필요한*엔트리*열기.md) | [NEXT: UC03. 원하는 범위와 규칙을 지정해 콜렉션을 직접 구성하기](uc03-원하는 범위와*규칙을*지정해*콜렉션을*직접\_구성하기.md)

1. ## **Summary**
    1. ### **One-line Definition**

- 현재 디렉토리에 존재하는 엔트리를 직접 선택해 정리하고, 디렉토리 구성을 관리가 용이하도록
  체계적으로 재배치∙정돈하는 흐름 2. ### **Purpose**

- 사용자가 UC01으로 디렉토리를 브라우징하며 엔트리를 확인한 이후, 엔트리의 프로퍼티 등을 정리하고
  불필요한 엔트리를 제거해 현재 기준에 맞게 이해되는 디렉토리 상태를 만들 수 있도록 하기 위함
- 활성 작업, 과거 버전, 참고용 등 다양한 엔트리가 섞인 상황에서도 단일 디렉토리에서 안전하게
  수동·반자동 정리를 수행할 수 있는 기본 플로우를 제공해, 이후 UC03 콜렉션 구성과 UC05 이후 채팅
  기반 파일 작업의 품질을 높이기 위함
- 이름 변경, 이동·아카이브, 삭제 같은 정돈 액션에 대해 최소 보장해야 하는 UX·확인 절차·Undo 기준을
  정의해, 이후 자동화·채팅 플로우에서 재사용 가능한 “디렉토리 단위 정리 사용성 기준”을 명확히 하기
  위함

2. ## **Scope**
    1. ### **In-Scope**

- 파일 매니저 윈도우 안에서 현재 디렉토리 페이지를 연 상태에서 수행하는 현재 디렉토리 기준 정돈∙관리
  작업
- 단일·다중 선택된 엔트리에 대한 기본 메타데이터 편집 동작
    - 이름 변경
    - 태그·색상 라벨 등 상태 플래그 편집
- 현재 디렉토리 및 그 하위 디렉토리 범위 안에서의 위치 이동
    - 선택된 엔트리를 기존의 다른 디렉토리로 이동
    - 새로 만든 하위 디렉토리로 이동
    - 동일 디렉토리 내 복제
    - 단순 복사/ 붙여넣기
- 불필요한 엔트리 정리
    - 스크린샷, 임시 산출물 등 저가치 파일 선택 후 휴지통으로 이동
    - 삭제는 항상 사용자의 명시적인 확인을 거친 뒤 실행
- 정리 작업 이후, UC01(파일 열기), UC03(콜렉션 구성), UC05 이후 채팅 기반 작업의 출발점이 될 수 있는
  정리된 디렉토리 상태 확보 2. ### **Out-of-Scope**

- 여러 디렉토리·드라이브를 가로지르는 규칙·조건 기반 대량 정리
    - 예: “지난 1년간 사용하지 않은 500MB 이상 동영상 파일 모두 별도 드라이브로 이동”
    - 예: “파일 내용에 ‘invoice’가 포함된 PDF를 전부 특정 폴더로 모으기”\
      → UC03, UC06에서 다룸
- 채팅을 통한 자연어 정리·질의
    - “이 폴더 정리 후보만 골라줘”, “이름 규칙 맞춰서 바꿔줘” 같은 요청을 채팅으로 던지고, LLM이
      제안·실행하는 흐름\
      → UC05에서 다룸
- 파일 내용 편집·주석 등 뷰어/에디터 역할
    - 현재 PRODUCT_THESIS Non-Goals에 의해 문서 내용 수정, 슬라이드 편집, 코드 수정 등은 외부 앱에서
      수행
- 스토라지 전체에서의 자동 규칙 실행
    - 로그인 시 자동 정리, 주기별 백그라운드 정리 등 사용자가 명시적으로 요청하지 않은 전역 자동화
      플로우
- 커스텀 프로퍼티 편집
    - 커스텀 프로퍼티 스키마 정의, 값 편집, 대량 편집 등 메타데이터 모델 수준의 관리는 UC02에서 다루지
      않음

3. ## **Flow**
    1. ### **Representative scenario**

- 사용자는 Voyager에서 오늘 정리하려는 프로젝트 디렉토리 탭을 연다. 디렉토리 안에는 최신본 피치덱,
  과거 버전, 리서치 PDF, 스프레드시트, 스크린샷·임시 파일 등이 한데 섞여 있어, 다음 작업 전에
  깔끔하게 정리해 두고 싶다.
- 곧 진행할 업무 기준에 맞춰, “이번에 실제로 사용할 파일만 남기고 과거 버전과 중간 산출물은 정리해
  두자”는 목표로, 리스트 정렬을 이름 또는 수정일 기준으로 바꾸고 버전별로 파일을 훑어본다.
- 최신본과 과거 버전을 한눈에 구분할 수 있도록, 관련 파일들의 이름을 인라인/Inspector에서 수정해
  접두사·버전 정보 등을 통일한다.
- 더 이상 자주 열어볼 필요가 없는 과거 버전 피치덱과 오래된 리서치 파일들을 다중 선택해 Archive 등의
  하위 디렉토리로 이동해 아카이브 영역으로 분리한다.
- 스크린샷, 임시 산출물, 테스트용 파일처럼 명확히 불필요한 엔트리는 한 번에 선택해 휴지통으로 이동해
  디렉토리에서 제거한다.
- 자주 참조할 핵심 파일(최신본 피치덱, 주요 지표 시트, 핵심 리서치 PDF 등)에는 공통 태그·라벨을
  부여해, 이후 UC03 콜렉션 구성이나 UC05 채팅 기반 파일 작업에서 쉽게 묶어 쓸 수 있는 상태로 만든다.
- 정리 작업이 끝난 뒤에는 같은 디렉토리를 열었을 때 “현재 기준으로 중요한 파일”과 “과거/참고용
  자료”가 이름과 디렉토리 구조만으로 자연스럽게 구분되고, 이후 브라우징·콜렉션·채팅 플로우의
  출발점으로 활용할 수 있다.

2. ### **Variations**

- Variation A: 이름 정리 위주 플로우
    - 대표 시나리오와 동일하게 정리 대상 디렉토리를 연 뒤, 이동·삭제보다는 이름 규칙 통일에만 집중하는
      경우
    - 예: `PitchDeck_v1_final_final.pptx`를 `2025Q1_Fundraising_Deck_v1.pptx` 형태로 통일하고, 버전
      접두사/번호를 맞춰 최신본·과거 버전이 이름만으로 구분되도록 정리한 뒤 작업을 종료한다.
- Variation B: Desktop/Downloads 임시 디렉토리 정리
    - 시작 디렉토리가 특정 프로젝트 디렉토리가 아니라 Desktop/Downloads 등 임시 디렉토리인 경우
    - 최근 생성일·파일 타입 등을 기준으로 정리 후보(스크린샷, 압축 파일, 임시 출력물 등)를 눈으로
      골라, 일부는 프로젝트 디렉토리로 이동하고, 일부는 `Later Review` 같은 하위 디렉토리로 옮기며,
      나머지는 휴지통으로 이동해 임시 디렉토리를 가볍게 만든다.
- Variation C: 태그/라벨 중심 정리
    - 향후 UC03 콜렉션 구성이나 UC05 채팅 기반 작업에서 사용하기 위해, 이름·위치 이동보다는
      태그/라벨을 통일하는 데 초점을 두는 경우
    - 예: 최신본·핵심 참고 자료에는 `key` 태그를, 정리 후보에는 `archive_candidate` 태그를 붙여 두고,
      나중에 이 태그를 조건으로 콜렉션을 만들거나 채팅 스코프로 지정하기 쉽게 맞춘다.
    3. ### **Exceptions**

- Permission error
    - 선택된 일부 엔트리가 파일 시스템 권한, 클라우드 동기화 상태, 파일 잠금 등의 문제로 이동·삭제되지
      않는 경우, 실패한 항목만 별도 상태로 표시하고 나머지 엔트리는 정상 처리
    - 실패 항목에 대해 “Finder에서 열기”, “권한 다시 요청” 등 우회 동작 제안
- Name conflict / target path conflict
    - 이동·복제 시 대상 폴더에 동일 이름 엔트리가 이미 존재하는 경우, 덮어쓰기/새 이름으로 저장/이동
      취소 옵션 제공
    - 사용자가 명시적으로 선택하기 전에는 기존 엔트리를 자동으로 덮어쓰지 않음
- Long-running / partial failure
    - 수십-수백 개 이상의 엔트리를 한 번에 이동·삭제하는 작업의 경우, 진행 상태를 표시하고 작업 중간에
      중간 실패 항목을 요약·표시
    - 일부 엔트리만 성공한 경우에도 성공/실패 엔트리를 나누어 표시해, 사용자가 실패한 엔트리에 대해
      개별적으로 후속 조치를 취할 수 있게 함
