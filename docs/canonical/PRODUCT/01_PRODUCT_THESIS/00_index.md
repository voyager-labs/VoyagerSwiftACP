## TL;DR

### 한줄 정의

탐색·논리적 콜렉션·대화형 조작·자동화를 하나의 흐름으로 엮어, 사용자가 지금 보고 있는 맥락에서 파일
작업을 안전하게 수행하도록 돕는 통합 파일 작업 워크스페이스

### 타깃 유저

- 1차 타깃: AI 에이전트 툴 숙련 엔지니어
    - 연구 논문, 코드, 데이터 포맷 파일을 다루며 AI 채팅 중 파일 맥락 전환 비용을 크게 느끼는 사용자
- 2차 타깃: 다중 프로젝트 인디 빌더
    - 제품 문서, 스크린샷, 데모 영상, 코드 파일을 프로젝트 단위로 재사용 가능한 구조로 운영하려는
      사용자
- 3차 타깃: 워크플로우 자동화 크리에이터
    - 원본 비디오, 이미지, 오디오, 에셋 파일을 다루며 아카이빙 자동화 루틴이 필요한 사용자

### 핵심 문제

1. **작업 단위가 아닌 폴더·기억 중심의 관리**
    - 파일이 "지금 하는 일"이 아니라, 폴더 구조와 사용자의 기억에 묶여 있어 현재 작업에 필요한 파일을
      찾고 이어가기 어렵다.

2. **머릿속 분류 체계와 맞지 않는 파일 검색·정리 수단**
    - 사람은 파일을 여러 속성, 프로젝트, 사람, 상태로 기억하지만 Finder와 검색은 경로·이름·태그
      정도만 다루어 실제 작업 방식과 어긋난다.

3. **반복되는 정리·검토 흐름이 구조화되지 않음**
    - 주기적으로 비슷한 정리·검토·공유 작업을 반복하지만, 그 흐름이 액션이나 템플릿으로 구조화되지
      않아 매번 폴더를 새로 만들고 파일을 옮기며 실수를 되풀이한다.

4. **파일에서 나온 인사이트와 의사결정이 분리되어 축적**
    - 여러 파일을 보고 내린 판단, 논의, 결론이 문서·채팅·회의록 등으로 흩어져 버려 "어떤 파일·근거로
      이 결정을 했는지"를 나중에 다시 추적하기 어렵다.

5. **AI 사용 시 파일 범위·처리 과정·결과를 통제하기 어려움**
    - AI에게 파일을 넘겨 질문·변환·요약을 시킬 수는 있지만, 어떤 파일이 어떻게 쓰였는지, 무엇이
      변경되는지, 되돌릴 수 있는지에 대한 통제가 부족하다.

### 핵심 가치

1. **Chat-integrated Flow**
    - 채팅 패널에서 현재 페이지, 선택된 파일, 필터 조건을 그대로 가져와 "지금 보고 있는 것"을
      기준으로 질문·명령을 시작하게 한다.

2. **Logical Collections**
    - 파일의 실제 위치와 상관없이, 조건·의미·작업 단위에 따라 콜렉션을 만들고 그 안에서의 작업 이력과
      상태를 함께 관리한다.
    - 같은 파일이 여러 콜렉션에 속할 수 있어, 사람의 멘탈 모델에 가까운 정리가 가능하다.

3. **Reusable Actions**
    - 자주 반복되는 필터링·정렬·이동·변환 흐름을 액션으로 저장하고, 다른 콜렉션이나 작업 집합에도
      재사용할 수 있게 한다.
    - 새로운 자동화를 만들 때도 기존 액션 조합으로 표현 가능한지 먼저 검토해 불필요한 복잡성을
      줄인다.

4. **Controllable Execution**
    - 대량 변경이나 AI 기반 변경을 실행하기 전에 영향 범위와 예상 결과, 실행 단계를 사용자에게
      보여주고, 부분 적용, 미리보기, 되돌리기가 가능한 안전한 실행 환경을 제공한다.

## Product Strategy: Orchestrated Delegation

Voyager는 모든 처리를 하나의 거대 모델에 맡기지 않습니다. 대화형 인터페이스는 사용자의 의도를
계획(Planning)하고, 검색·정리·변환·자동화 등 목적에 맞는 실행 체계로 단계별로 위임합니다. 이를 통해
AI의 유연성과 파일 작업의 결정론적 안정성을 동시에 확보합니다.
