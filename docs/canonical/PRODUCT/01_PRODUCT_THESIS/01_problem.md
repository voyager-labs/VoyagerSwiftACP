# Problem

## P01. 필요한 파일을 다시 찾기 어렵다

- 상황
    - 작업에 필요한 파일은 이미 어딘가에 저장되어 있어도, 실제로 다시 쓰려는 순간에는 파일명, 경로,
      저장 위치를 먼저 떠올려야 하는 경우가 많다.
    - 사용자는 파일을 프로젝트, 목적, 최근 작업 맥락으로 기억하지만 기존 탐색 방식은 그 기억을
      직접적인 탐색 기준으로 다루지 못한다.
- 결과
    - 지금 필요한 파일을 찾는 과정이 작업 이해보다 기억 정확도와 재탐색 반복에 더 크게 좌우된다.
    - 필요한 파일을 찾는 데 시간이 오래 걸릴수록 이후 작업 시작도 함께 늦어진다.

## P02. 파일을 일관되게 정돈하기 어렵다

- 상황
    - 기존 파일 정돈은 폴더 위치와 파일명 규칙을 중심으로 이루어진다.
    - 그러나 하나의 파일은 여러 프로젝트, 상태, 목적에 동시에 걸쳐 사용되어 단일한 위치 기준만으로는
      같은 체계를 계속 유지하기 어렵다.
- 결과
    - 정돈은 기준이 축적되는 작업보다 위치와 이름을 계속 손보는 유지 작업이 된다.
    - 시간이 지날수록 최신본 판단, 버전 관리, 재사용 준비가 더 어려워진다.

## P03. 정리 기준과 맥락이 체계로 축적되지 않는다

- 상황
    - 사용자는 파일을 프로젝트, 주제, 상태, 대상자, 활용 목적 같은 맥락으로 이해하지만 이런 기준은
      파일 시스템 안에 구조적으로 쌓이지 않는다.
    - 이전 작업에서 사용한 분류 기준과 연결관계도 머릿속, 메신저, 노트, 임시 규칙에 흩어진 채 남는다.
- 결과
    - 어떤 파일이 왜 중요한지, 어떤 파일끼리 함께 봐야 하는지 매번 다시 판단해야 한다.
    - 시간이 지나도 정리 기준이 자산으로 남지 않아 다음 작업이 이전 체계를 이어받지 못한다.

## P04. 그래서 파일을 다시 활용해 새로운 산출물을 만들기 어렵다

- 상황
    - 파일은 단순 보관 대상이 아니라 새로운 문서, 공유 자료, 의사결정, 다음 작업의 입력으로 계속 다시
      활용되어야 한다.
    - 하지만 필요한 파일을 다시 찾기 어렵고, 정돈이 흔들리며, 맥락과 기준이 축적되지 않으면 파일
      집합을 빠르게 재구성하기 어렵다.
- 결과
    - 사용자는 기존 자료를 바탕으로 더 빠르게 이해하고 조합하고 산출물을 만드는 대신, 매번 다시 찾고
      다시 정리하는 데 시간을 쓴다.
    - 파일은 축적되는 자산이 아니라 다시 다루기 어려운 보관물로 남아 지식 재창출 속도를 떨어뜨린다.

## P05. 좋은 파일 관리 체계를 직접 구축하고 유지하기 어렵다

- 상황
    - 좋은 파일 관리 체계를 만들려면 정리 기준을 세우고, 반복되는 파일 집합을 정의하고, 유지 규칙을
      계속 손봐야 한다.
    - 그러나 이 과정은 사용자가 직접 설계하고 운영해야 할 항목이 많아질수록 빠르게 부담으로 바뀐다.
- 결과
    - 많은 사용자는 필요성을 느껴도 체계를 끝까지 구축하지 못하고 다시 임시 검색과 수동 정리 방식으로
      돌아간다.
    - 파일 관리 도구는 작업을 돕는 시스템이 아니라 계속 관리해야 하는 또 다른 작업으로 인식된다.
