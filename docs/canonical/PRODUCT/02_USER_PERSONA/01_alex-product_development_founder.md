## Context

1. ### 기능을 다시 열 때마다 작업 시작 비용이 커진다

- 핵심 상황
  - 하루에도 여러 번 같은 기능으로 다시 돌아오며, 구현하다가 QA 메모를 확인하고 다시 데모 캡처를 손보는 식으로 맥락이 계속 바뀜
  - 머릿속에는 “이번 기능”이 하나의 묶음으로 남아 있는데 실제 파일은 코드, 문서, 캡처 자료로 흩어져 있어 다시 모으는 단계가 필요함
- 현재 방식
  - IDE, Finder, 문서 툴을 오가며 관련 자료를 다시 열고, 빠진 파일이 있으면 또 찾으러 감
  - 조금만 시간이 지나도 어떤 조합이 기준 세트였는지 기억에 의존해야 함

2. ### 구현이 끝나도 같은 자산을 다른 설명 맥락으로 또 넘겨야 한다

- 핵심 상황
  - 기능을 만든 뒤에는 QA 확인, 데모 설명, 고객 공유, 투자자 업데이트처럼 같은 자산을 다른 맥락으로 계속 전환해야 함
  - 결국 코드 변경 하나가 설명 자료와 캡처 기준까지 함께 흔드는 경우가 많음
- 현재 방식
  - 기능을 완성한 뒤 다시 캡처 자료와 설명 문서를 맞추고, 최신본인지 확인하며 한 번 더 정리함
  - 구현이 끝나도 “다음 설명 맥락으로 넘어가는 일”이 새로운 파일 재조립으로 이어짐

## Pains

1. ### 기능 구현 맥락으로 다시 들어올 때 흐름이 자주 끊긴다

- 필요한 자료가 이미 있어도 관련 코드, 스펙 문서, QA 메모, 데모 자료를 한 번에 다시 여는 일이 쉽지 않음
- 작업 이해보다 먼저 “어떤 파일을 다시 열어야 하지?”를 떠올려야 해서 시작이 늦어짐
- 구현 그 자체보다 맥락 복원 비용이 커질수록 빌드 루프가 자주 끊김

2. ### 같은 기능 자산을 맥락별로 돌릴 때 매번 다시 설명해야 한다

- 내부 확인용으로 보던 자료를 QA·데모·설명 쪽으로 넘길 때마다 어떤 파일을 같이 봐야 하는지 다시 정리해야 함
- 캡처 하나, 문구 하나만 바뀌어도 관련 자료 전체의 최신성 확인이 다시 필요해짐
- 기능 하나를 끝낸다는 감각보다, 같은 자산을 여러 번 다시 정리하는 감각이 더 강해짐

## Goals

1. 특정 기능 맥락으로 돌아왔을 때 관련 파일 세트가 바로 열려 구현 판단을 끊김 없이 이어갈 수 있는 상태
2. 같은 기능 자산을 QA·데모·설명 맥락으로 넘길 때 다시 처음부터 자료를 조립하지 않아도 되는 상태
3. AI 보조 파일 작업을 실행할 때 범위와 결과를 미리보기로 확인하고, 필요한 만큼만 적용하거나 되돌리기 할 수 있어 안심하고 맡길 수 있는 상태
